# 六步连线的通行口径、禁用与页面边界

Status: implemented
Date: 2026-09-20

2026-09-21 新增普通补全与输入挑战，原六步玩法保留为探索模式。另增双人判断：先判断是否直接认识，不认识时再选共同中间人。四种模式复用原双侧立绘，默认仅干员；普通模式采用一至三处空位，异格独立展示但共享人物身份，答案可展开多条。独立进度及输入匹配边界见[三模式决定](2026-09-21-three-game-modes.md)。下文通行口径、原资料判定和立绘约束继续有效。

用户要求在关系网站增加 GAME 分区，先实现六步连线，默认禁用博士、阿米娅、凯尔希并允许自定义限制。随后明确修正游戏判定：“有连线就算，不要管相识是什么种类”。既有网页的视觉系统须保留。

游戏将 API 当前提供的所有关系作为无向边；数据库、原档案展示及证据继续保存原始种类和方向。曾考虑只用相识关系，但这不符合用户后续明确规则。关系图连线已按无箭头展示，统一游戏通行也使玩家看到的连接与实际可走连接一致。不得把“游戏可双向走”反向解释成剧情双方相识。

范围与禁用先构成题目专用图，BFS 和玩家走步都只使用此图。出题遍历有界最短距离后等概率采样，替代有限随机重试；后者实现简单，但在自定义禁用较多、题目稀少时会误报无解。设置草稿必须先找到有效题再替换现有规则和进度，不能将题目走到一半的关系图直接换掉。

纯前端单人游戏复用正式只读 API，避免为可公开计算的路径增加后端接口或写入资料。进度仅保存在本浏览器，恢复时检查数据指纹和整条路径。增加具有排名意义的服务端成绩、同步或统一每日题时，应重新评估服务端出题、数据版本与成绩校验；当前客户端结果不应被当作可信排行榜成绩。

`frontend/src/main.ts` 根据 `/game/` 独立加载游戏 Vue 根组件，原站继续使用既有 `App.vue`。复用旧图谱整套页面能直接获得画布，但它的全局监听、原文面板及历史状态与游戏规则不同，因此仅复用字体、令牌、头像和 API。独立入口无需增加路由依赖；新增导航使用普通路径链接，不进入旧 `data-page` 分区处理。未来若各分区需要保留共享应用状态或更复杂嵌套导航，再考虑统一路由。

立绘扩展按用户确认采用“左侧当前人物，右侧固定终点”，不能改为固定起点。默认彩色前景读取精一／基础 `illustId`，灰色背景使用实际精二皮肤对应的 `portraitId` 半身构图。用户随后要求点击背景交换精一、精二，并强调两个阶段的背景都需要同等的人脸特写效果，因此补齐精一半身图；不能用全身图简单灰化作为背景备用。两套半身图合计约 14.8 MB。NPC 与没有精二的干员不复制前景制造假背景。

切换只改变本组件的观赏状态：新当前人物恢复精一，持续挂载的终点保留所选阶段，不改动本局存档。先并行加载并解码下一组图，再沿原站相向横移语法同时交换；失败保留原图，忽略加载或转场中的重复点击，人物销毁后不接纳旧请求。背景点击区只占立绘外侧，另有具名的可聚焦按钮与加载／重试反馈，不能覆盖中间游戏操作区。精二前景场景的外侧上角渐隐，避免道具盖住背后的脸。

资源在构建前下载、校验并转换，本地清单按人物 ID 对应两层；使用远程链接可以减小仓库，但会把游玩时的网络可用性、可变分支与跨站请求交给素材站，因此当前保留约 148 MB 的可部署 WebP。浏览器只请求正在显示的两人图片，切换时才请求对应的另一组，索引共享，原始 PNG 留在忽略的缓存中。未来扩展全皮肤或人物数量明显增加时，可以保留同样的版本索引接口并评估独立静态素材托管。素材缺失不阻断游戏，头像备用状态明确提示并允许重试。

吸附立绘的包含块必须止于本局操作区，规则和关系依据独立排列在后面。把立绘与规则放进同一个多行 Grid 会让吸附继续进入下方区域，导致滚动后的遮挡；仅调整 z-index 不能保留两边内容的可读性。当前使用独立 Grid 与绘制边界约束，换题放到撤回、提示旁边。回归使用实际的“休谟斯 → 吉星 → 遥，终点米奥”局面，在多个滚动位置检查立绘与规则区域不相交，并实际点击规则、原文和换题。

实现、命令、验证证据入口和状态边界集中在 [GAME.md](../../../../docs/GAME.md)。该文档与 `network.ts` 的入口注释共同维护游戏规则，避免与原站关系判定混用。
