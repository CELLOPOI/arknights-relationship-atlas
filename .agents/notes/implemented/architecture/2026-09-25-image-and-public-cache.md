# 图片交付与按发布版本缓存公开资料

Status: implemented
Date: 2026-09-25

人物比较原先直接预加载完整立绘，普通图片和字体使用重新验证缓存。图谱则先查出所有人物与关系、编码完整响应后才判断 ETag；喜好目录把固定名录、当前开关和服务器时间放在一个禁用缓存的请求中。慢网下既有重复传输，也有重复构造公开数据的成本。

图片沿用现有完整构图缩略图。人物比较按原图 URL 精确匹配外观，使用固定派生流程的实际宽度生成 `srcset`，`sizes` 结合卡片宽度和 contain 后的图幅高度；预加载与卡片使用相同候选。无法确认派生尺寸的历史或 NPC 图片继续用原图，不借用其他形态或裁切半身图。放大仍指向完整原图，图片失败继续禁止选择并提供重试。人物、皮肤视图首次打开时才挂载，防止隐藏目录提前下载；打开过的视图保留状态。

固定图片 URL 使用 `/media/<内容摘要>/<原路径>`。构建从两份固定文件清单的路径与 SHA-256 分别生成摘要和 Caddy 路由，前端使用同一摘要。服务器只为当前版本、对应素材目录中实际存在的文件返回一年 `immutable`；旧版本、缺失文件、非素材路径返回不缓存的 404。未改动的素材只保留一份物理文件，通过路由别名提供新地址；旧 URL 继续重新验证。通用 unknown.svg 随应用代码变化，保持旧缓存边界。字体由 Vite 读取原文件生成内容哈希文件，保留版权声明及 same-origin 字体响应头。

逐文件内容地址能避免添加一个素材就使整组缓存失效，但需要传送或维护更大的运行时映射。本次选择两组固定清单摘要，前端只增加两个短版本值，代价是组内素材变化会使整组 URL 改变。只给原 URL 加一年缓存更简单，但会把替换后的内容藏在旧缓存里，因此不采用。未知旧版本不重写到最新内容；更新素材后长期停留的旧页面可能需要刷新。

图谱缓存键包含响应格式版本、scope 与正式发布元数据，在现有只读一致性快照内先读取发布版本。命中 ETag 时直接 304；其余请求复用已编码 JSON。没有正式版本或明确关闭正式资料管理时继续按实际内容构造，不使用版本缓存。喜好新增 `runtime/` 返回实时配置、服务器时间和当前名录版本，并初始化 CSRF；`directory/?version=...` 只返回该当前版本的公开名录。版本不一致返回 409，客户端有界重新读取，禁止拼接不同版本的目录与个人状态。旧 `catalog/` 保持兼容。

公开 JSON 使用 `public, max-age=0, must-revalidate`，每次请求仍核对当前版本；喜好还先检查维护开关与现有来源限流。只有与访客无关的目录响应不带 Cookie 变化维度，不创建身份。实时状态、身份、题目、写入和统计结果继续禁止存储。每个 worker 最多缓存八份已编码响应，不向数据库缓存表写入，也不依赖跨进程失效通知。发布更换键即生效；更改公开响应结构时必须更新缓存键的格式版本。

进程缓存让每个 worker 的首次请求仍需构造一次数据；共享缓存可减少这部分工作，但会增加外部服务或数据库缓存写入，并与图谱只读事务冲突。本次复用本机内存缓存，保留限流和发布边界；未来按实际内存、冷启动次数和数据体量再评估共享缓存。缓存不代替大陆运营商线路验证，也不改变资料发布、投票幂等或统计算法。

验证入口为 `make check`、独立 PostgreSQL 的 `make check-postgres`、`scripts/verify_caddy_proxy.py`、`scripts/verify-image-delivery.mjs` 和既有喜好 UI 回归。新增用例检查冷缓存 304、热缓存跳过完整查询与编码、不同 scope、发布失效、维护开关、目录版本冲突、全部 1,361 张缩略图真实宽度、原图回退以及字体/图片的真实缓存头。浏览器使用真实素材和 Caddy、合成 API，记录不同像素密度下实际选图及重复访问传输量；不代表真实手机或运营商延迟。

本机 Chromium 的同一对阿米娅/维什戴尔完整构图，在 390×844、DPR 2 和 1440×900、DPR 1 下，所选文件合计由原图 581,822 字节降为 125,046 字节（减少 78.5%）；手机 DPR 3 为保证清晰度选择一张缩略图与一张原图，合计 430,002 字节（减少 26.1%）。三个场景刷新后，被测图片和字体的 Resource Timing 传输量均为 0。此结果衡量文件字节与本机浏览器缓存，不把字节降幅当作运营商延迟降幅。

缓存语义参照 [HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[响应式图片](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img)与 [Caddy 路径处理](https://caddyserver.com/docs/caddyfile/directives/handle_path)。
