# 正式资料由 GitHub 审核发布，后台只维护反馈与候选

Status: implemented
Date: 2026-09-20

2026-09-21：关于日常资料权威来源、单条候选导出和 Git 审核发布的决定已由[后台资料发布](2026-09-21-editorial-publication.md)取代。以下保留历史理由与验收；稳定 ID、方向、原文、条件叙事、锁和事务、备份恢复边界继续有效。

用户选择公开首版提供图谱、游戏及匿名反馈，以 GitHub Issues 和 PR 为主要维护入口，正式资料以合并结果为准。原实现以数据库为权威，后台直接改资料；同时接受 Git 修改会造成双向覆盖，摘要去重导入也不能检测漂移或表达撤下。

保留 Django、PostgreSQL 和资料模型，正式输入改为可审查的 `data/source/`。确定性编译生成含 Git commit、资料与文件摘要、预期前版及素材版本的发布包。资料建包与生产预览/应用共用资源清单约束，提前拒绝素材版本不匹配和公开头像断链；前端构建另核对实际文件及立绘索引。后台保存私有反馈和字段候选，导出带基线的修改包供维护者提交 PR，不持有自动 GitHub 写入凭据。生产强制受控正式资料写入，旧社区默认关闭。

维持数据库为权威能继续即时后台修改，但与用户要求不符；Git 与后台双向合并保留即时编辑，却需要三方冲突与漂移治理；纯静态交付能降低运行服务成本，但仍需为必需的私有反馈和编辑建立服务。当前选择使修订等待审查发布，换取单一来源、明确版本及可追溯修改。

发布和候选操作按同一顺序锁定发布状态。预览绑定整个包、数据库正式资料摘要及当前版本，应用时再次核验并原子写入资料、审计和发布记录。缺失记录不能默认为删除，身份与独立证据也有显式公开状态；稳定关系不能换端点，证据不能换关系。读请求使用只读可重复读事务，防止一个响应混合两次发布。资料回退建立新版本，保留后来收到的反馈、账号和内部记录；灾难恢复另行演练。

当前开发检查见[开发指南](../../../../docs/DEVELOPMENT.md)，资料往返与事务验收见[后台验收](../../../../docs/EDITORIAL_VALIDATION.md)。初始化发布仍要求可信的干净 Git 输入；本地 dirty 包在生产被拒绝。日常资料维护遵循承接决定，不恢复已被替代的 Git 审核发布入口。

上游派生规则继续有效，见 [NPC 来源决定](2026-09-20-npc-derived-import.md)，其“直接导入是日常写入口”的旧范围由本决定取代；重新生成只产生候选差异。完整格式、操作与限制见 [资料格式](../../../../docs/DATA_SOURCE.md)、[发布流程](../../../../docs/DATA_RELEASES.md)、[后台候选](../../../../docs/DATA_CANDIDATES.md)。图谱实例所有权与资源释放的独立取舍见 [生命周期](../../../../docs/GRAPH_LIFECYCLE.md)。
