# 经验证的容器镜像与固定摘要发布

Status: implemented
Date: 2026-09-23

完整镜像归档会重复传输已有依赖和素材，且 Web 将固定素材与应用产物合并为一个层，小幅程序改动也会改变大层。需要让检查通过的源码产生可复用的镜像，同时保留开发仓库与个人运维的边界。

主分支源码检查通过后，CI 构建 API/Web 镜像并执行运行检查，以 GitHub 任务令牌发布到 GHCR。两项镜像检查都成功才公开包含完整摘要的 Release；实例使用摘要确定内容。PR 执行容器检查但不发布。已公开的版本清单不被重跑覆盖；上传未完成时保留草稿，重跑可补全。构建不接收任何实例凭据或真实配置；个人更新工具、维护步骤与状态继续留在源码仓库外。

Web 根据 public 文件清单分离固定素材和 Vite 应用输出，逐文件核对构建结果以拒绝覆盖，保留全部 URL 与许可文件。API 分离依赖、素材、清单、名录和源码；复制时设置归属，避免递归 chown 生成第二份素材层。固定素材规范化元数据，BuildKit 按服务缓存构建层。

服务器从 Git 拉取源码也能减少源码传输，适合有构建资源的环境，但需要在运行实例维护构建工具链。镜像归档容易离线传递，也可继续用于离线恢复，但常规更新难以复用现有层。当前选择 CI 构建与 Registry 拉取，增加镜像仓库、包权限和发布清单维护，换取实例无需编译和按已有层复用。首次下载、素材或基础镜像变化仍可能很大；没有实测时不承诺网络节省比例。

发布清单表示构建产物可用，不表示数据库、资料或实例已更新。固定摘要、私有配置边界以及两项镜像共同发布是持续约束。格式与验证入口集中在[容器构建说明](../../../../docs/CONTAINER_IMAGES.md)。

本次验证覆盖完整应用检查、版本清单和分层工具测试、真实镜像构建与运行检查。镜像仓库首次发布须在主分支工作流执行后核实，实例更新另行验收。
