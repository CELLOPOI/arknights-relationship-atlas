# 喜好首版与 V2：独立业务、名录、贡献上限与统计版本

Status: implemented
Date: 2026-09-23

后续[人物合并与异格独立人气方案](../../../../docs/PREFERENCES_IDENTITY_PROPOSAL.md)已实施，补充下文的单题双榜决定；旧 V2 校准仍作为历史证据保留。

喜好包含长期当前登记与限额随机任务，不能复用图谱资料编辑或游戏本地进度作为正式票据。首版在既有 Django atlas 应用中增加独立业务表，沿用 PostgreSQL、原生事务和现有固定素材流程；人物稳定 ID 只引用正式发布资料，不开启旧社区接口。统一 Vue 页面通过查询参数与 History API 切换人物/皮肤，以保留草稿、滚动和同一匿名身份，不引入全站路由迁移。异格及职业形态为独立可选形态，首版/V2 随机榜按统一人物 ID 计票，后续扩展为一次形态回答生成两个统计视图。

所有业务写入按控制行、参与者行锁顺序串行化，名录发布同样获取控制行。只锁参与者可提高不同访客并发，但发布、风险复核、聚合及当前状态的锁顺序更复杂；首版选择容易审查的一致性边界，代价是全局写吞吐受到控制行限制。2026-09-25 起统计计算移到事务外，仅取数与发布持锁，详见下文[聚合锁边界](#聚合锁边界2026-09-25)。其余写入顺序保持不变；真实容量仍须测量，不能将消除计算期锁等待等同于整体吞吐已达标。

请求以持久操作回执、唯一约束和对象版本共同约束；响应丢失时原内容原键重试，不凭前端防抖保证幂等。随机派发预留额度，首次成功回答为最终结果，自然过期保留额度。任意全局名录发布都作废旧待答并退额，包括名称勘误；精确识别每种修改影响可减少作废，但会扩大兼容性判定面，当前采用保守版本边界，维护者应合并微小修订。已受理记录保留原始版本。人物形态确认按合格候选集合派生版本，文字变化不触发重确认；外观集合显式版本不得对应不同历史集合。稳定 ID 不允许跨历史版本换归属。

当前支持、形态、皮肤各保留一份有效状态，历史事件用于截止点回放；清理不能删除当前贡献或必需锚点。统计按名录、算法、素材、截止点和修订保存；显式历史纠正创建修订，跨版本不直接画升降。选择表只存当前状态更短，却无法说明历史支持净变或风险复核，因此保留事件与不可变快照。保留周期以外不可声称完整重算。随机模型采用正则化 Bradley–Terry 与参与标识成组重采样；样本/网络/稳定性门槛同时满足才排位，不能用先验把无数据人物排出精确名次。

首批独立 preferences 素材包固定来源提交、摘要、人物/形态/外观归属与完整集合。其准备可读取相邻资料，正常构建只使用仓库内输入。宽构图采用保留全幅的缩略图；自动脸部裁切可以增强肖像，但易剪掉服饰和人物，首版没有把构图中心当作已逐图精修的焦点。记录真实 focus.reviewed 状态，并提供全幅预览；后续扩充目录应逐批审读，不能删掉失败图片后把部分目录当完整投票。

验证与适用范围见[运行说明](../../../../docs/PREFERENCES.md)：SQLite/PostgreSQL 全套回归、并发与版本冲突、干净输入构建、四视口合成交互、真实浏览器/API 提交、素材联系表目视复核，以及独立 PostgreSQL pg_dump/pg_restore。两周公开试运行、真实访问容量、匿名防刷效果与完整辅助技术兼容性仍未验证。匿名来源摘要不是独立真人，风险只能暂缓并接受有记录的复核；不接入未经目标环境验证的外部验证码。

## V2 实施决定（2026-09-23）

皮肤目录后续修正：六个已核对的临时支援实例只在目录和人物档案的外观入口合并，保留来源形态、历史登记与旧详情链接。选择展示映射而非删除名录，是因为稳定 ID 与既有登记不能悄悄转挂；真正异格、阿米娅职业形态和领主·Sharp 继续独立。来源目录仍为 446 形态，展示目录为 440 项。棘刺基础/精二半身裁切改用完整派生图像素定位，修正图采用新路径，旧文件哈希不变；名录与素材版本同步更新，经受控发布后生效。

该修正通过 `make check`、4 项目录边界测试，以及 `verify-preferences-skin-fixes.mjs` 的 1440×900 / 390×844 浏览器检查。浏览器使用真实目录与素材、合成 API 状态，验证重复项、异格保留、基础/个人精二卡面和旧 Touch 详情链接；没有操作业务库或部署线上。原有 4,339 个文件的清单条目逐项保持相同，仅新增两张修正版。

按用户后续明确要求，将首批目录扩展为固定截止点446形态/1,361外观，NPC按93剧情单元审读上下文和独立立绘选184人，保留四单元缺项。候选补充经原资料修订服务审核/预览/发布，不改稳定人物身份或捏造关系。正式发布额外绑定引用的喜好头像清单版本和文件哈希，防止审核后换图。

半身卡面从真实图像离线派生，全部联系表复核，异常单独裁切；完整原构图继续保留。固定清单保留V1全部文件，普通构建不需要相邻资料工程、原图缓存或人脸模型。相比每次在浏览器统一cover，派生图和按源哈希绑定焦点能在小屏稳定显示脸肩，代价是约87.6MiB的独立半身资源与维护复核成本。

窗口内最新有效无序对位采用对称 `min(1,50/n_u,1/d_ui,1/d_uj)`，胜场与边都加权；28/84天各自完整计算，周额度不重置统计预算。聚类bootstrap副本保留已算权重。保留K=50、L=1、先验0.5，是限制长期直接贡献与可解释性的产品取舍；模拟中L=2恢复略高不能自动推翻已选择的人物贡献上限。约束输入不保证最终分数影响封顶，单题只得1，多身份集中参与仍能显著移动分数。

综合榜明确为70%近84天随机分百分位+30%当前支持百分位，固定合格E，保留分项并公开权重敏感性。用户追加综合榜替代首版不合成的范围决定；本命、外观、练习不加分。零支持的中秩仅用于实际观测值；冷启动与缺失不补50。观察网络断开不靠先验拼榜，趋势按参数、参照、候选、素材与修订分段。

跨入口使用统一页面顺序而不是“是否回atlas”决定方向；会话草稿脱离组件生命周期，未知结果保存原路径/参数/操作键，迟到响应不得派题。50次休息与统计K独立配置。未引入新的全站路由框架。

实际验证：155项后端、独立PostgreSQL、四视口真实/模拟接口、全素材解码、独立干净构建与图谱/游戏回归通过。模拟600标识/12,000判断恢复96.77%，单次区间覆盖28/32，不是总体95%覆盖证明。范围、证据和未完成项见[V2验收](../../../../docs/PREFERENCES_V2_ACCEPTANCE.md)，公式与后续重评依据见[统计说明](../../../../docs/PREFERENCES_STATISTICS.md)。继续关注公开试运行下的网络连通、匿名新身份、有效样本集中、区间覆盖和全局锁吞吐；未部署线上。


## 单次采集与双榜（2026-09-23）

用户明确预设某个形态的选择代表对所属人物的偏好，并拒绝增加第二套问答。新随机题保存双方实际 Subject 与当时人物 ID，一题一次额度；结果默认“干员分开”，可切换“人物合并”。合并视图映射胜负双方，再按同标识/人物对保留最新判断并重新计算 K/L、BT 和百分位。未出场的同人形态不追加胜负，不能把形态分相加或取最大作为人物分。

抽样先人物后形态，共享人物曝光预算，避免仅因形态多而获得更多人物机会。新形态支持按人物并集占用 15 个名额，本命最多 3 人且同人只选一个形态。历史人物支持单列保留，旧票不猜测形态；迁移 0011 只补字段和快照 person 口径，不复制原始票据。事件、任务和快照复用现有事务/幂等边界，scope 纳入查询与序列，算法升级为 bt-dual-scope-v3。

独立两套问答能更准确区分用户判断目标，但会增加参与负担，故按用户预设使用同一次回答。代价是人物合并榜反映本站展示形态分布下的偏好，不是另行采集的人物总体问卷；新形态分摊曝光，冷启动可能更慢。旧 V2 模拟不证明新形态池已校准，公开试运行仍需观察连通性、区间与展示分布。

浏览器真实 API 检查覆盖桌面/手机题面恢复、实际形态记录、同人名额、本命替换、旧登记保留及双榜切换，产物位于 `.runtime/verification/preferences-identity-ui/`。新增后端测试覆盖映射/去重/上限、旧 schema 升级与快照隔离；运行证据见[复验说明](../../../../docs/PREFERENCES.md#复验)。所有写入只在独立测试库，未发布业务数据或部署线上。

按用户要求，滑动翻页只覆盖首页→关系→游戏→喜好；来源与版权页保留普通链接及原生滚动，退出手势翻页链。桌面滚轮与手机触控均检查喜好底部停止、来源页上下边界不跳转。

## 聚合锁边界（2026-09-25）

原 `aggregate()` 从取数到全部拟合、重采样及快照写入都持有控制行锁。统计耗时一旦超过 Web worker 的等待期限，新身份、派题和投票会在同一行排队，最终超时；只读就绪接口正常不能证明参与流程可用。

改为三阶段：在控制锁下物化 84 天随机回答与截止点登记状态，记录当前名录、修订号及保留边界；提交事务后用同一份输入计算两种口径与两个窗口；重新加锁核对三个版本值，再原子发布整批快照。审核、名录发布或清理引起版本变化时拒绝本轮结果，后续重算；普通截止点后投票可继续写入。两个事务使用 `durable=True` 拒绝业务外层事务，防止调用者无意延长持锁时间。显式修订号与快照一起提交，计算或发布失败不留下部分结果，也不消耗该次修订号。

增加 worker 或延长请求超时能缓解少量等待，但不能解除控制行排队；减少重采样会改变既有统计约束。全面拆分控制锁有更高并发潜力，却会扩大名录发布、风险审核与业务写入的一致性改动。本次保留这些既有边界，只移出耗时纯计算，不引入任务队列或改变算法版本。

代价是将整份统计输入暂存在内存，版本冲突会浪费本轮计算。取数与快照发布仍会短暂持锁；后续应按实际输入量、持锁时间、内存和 CPU 占用评估分页取数、批量发布或独立统计进程的资源限制。当前没有生产容量基线，不声明速度提升倍数。

`make check` 与独立 PostgreSQL 的 `make check-postgres` 通过，后端共 181 项，SQLite 跳过 13 项 PostgreSQL 专属检查。并发用例覆盖统计计算期间新身份、取题、投票与原操作键重试；将统计函数在测试进程内替换为修复前实现时，同一用例因控制行锁超时失败。新增用例还检查审核/名录/保留范围冲突、计算异常、发布失败的整批回滚及外层事务保护。本次无数据库迁移，所有验证只使用隔离的合成数据，不代表外部实例已经部署。

## 清理与异常恢复（2026-09-25）

后台控制表单携带修订号，在校验时锁定当前控制行直到保存结束；旧表单提示重新加载，只将实际修改的开关和暂停对象写入最新记录。避免后台保存覆盖同时发布的名录、保留边界或统计状态；无修改不增加修订号。

`purge_preferences` 先在短暂的 `durable=True` 事务中推进明细保留边界，提交后释放控制锁，再按最多 500 条一批清理。聚合发布沿用保留边界校验，拒绝清理开始前取得的旧输入。这样清理期间可以继续创建身份、派题和回答；代价是整次清理不再全部回滚。中途失败时保留边界已保守缩短，未清完的记录可安全重试，不将残留数据误报为可完整历史重算；外层业务事务会被拒绝，避免重新延长控制锁。

旧支持、选择及选择纠正事件通过数据库 `Exists` 查询判断是否已有同参与者、同对象且不晚于保留边界的后续事件，时间相同时按主键排序，保留边界前的最后锚点。边界后的新事件不能替代该锚点。迁移 `0012_preference_event_anchor` 只增加索引以支持该查询，不改写业务数据。过期限速记录在实际删除时再次核对到期条件，保留选取后被并发续期的记录。

前端 JSON 请求设置 20 秒期限，覆盖连接与正文读取；写请求结果未知时保留原内容和幂等键，并释放操作中的状态供用户重试。题目已过期、已回答、不存在或候选不可用时移除旧题，恢复取题入口。选择页按图片 ID 与 URL 保留加载状态，撤下或替换失败图片后不会残留无法解除的确认阻塞。

合并工作区的图片与公开缓存改动后，`make check` 和独立 PostgreSQL 的 `make check-postgres` 均通过，共 193 项后端测试；浏览器覆盖请求超时后原键重试、四类失效题目恢复和失败图片撤下后的实际确认。后端覆盖后台修订冲突、清理锚点、限速续期、失败重试、外层事务保护，以及暂停清理时并发创建身份、派题和回答。测试仅使用隔离合成数据；批量清理仍占用数据库资源，未据此声称生产容量达标。


## 个人喜好榜与参与额度（2026-09-25）

个人练习原来只保存本机记录；新增个人榜后，小样本的对手差异、旧形态快照与断开的比较网络不能被包装为完整偏好次序。榜单复用当前浏览器最近 500 条练习，以当前合格人物 ID 合并形态，默认仅干员，另提供干员 + NPC；范围同时控制统计和练习出题。两端都在范围内才采用，撤下人物、坏记录和未知胜方排除。没有判断的人物不排名。

同一无序人物对取最新明确选择或平局，后来的跳过不覆盖已有判断。选择采用正则化 Bradley–Terry 的成对似然，对数能力 L2 系数固定为 1，平局作为各半观测；逐坐标二分求严格凸目标的最优值，有界迭代与稳定 ID 顺序保证可复验。简单胜率便于解释，但会把对手难度和极少判断当作稳定偏好；按时间更新 Elo 实现简单，却会让旧记录遍历顺序影响结果，因此这里从当前有效对位统一拟合。先验限制全胜/全败的极端值，不代表已获足够证据。

观察网络的每个连通组独立排名、各从 1 开始，组间不分高下；页面只显示暂定名次和比较次数，不展示为精确概率或置信区间。练习优先连接已有分组，否则约 35% 的引新选择与已有接近人物的缺失对位交错；无法补旧对位时直接引新，软避开紧邻重复及近期不熟悉人物。该比例是覆盖与细化之间的产品取舍，不宣称信息增益最优。个人榜不读取正式答案、不发正式任务、不计入公共贡献。存储失败显示提示并保留当前页；清空练习同步清榜。跨设备同步、完整历史及形态独立个人榜需另行设计。

公共目录为 581 人物/624 比较对象。参与额度从每周 120、28 天 480、同人物 3 次展示调整为 300、1,200、6；若只提高总额度而保留 3 次人物上限，理论上 871 道就会用完全池曝光。配套提高展示上限改善覆盖，但保持 84 天对位限制、整窗 K=50/L=1、短时限流和全部公共入榜条件。全池最低样本量及其必要条件性质集中说明于[统计文档](../../../../docs/PREFERENCES_STATISTICS.md#参与额度与全池样本下限2026-09-25)。额度由设置直接读取，不清空已用计数，也无需迁移。

验证入口为 `npm --prefix frontend run test:preferences`、`make check`、专用 PostgreSQL 的 `make check-postgres` 和 `scripts/verify-preferences-ui.mjs`。新增纯函数用例检查链式偏好、对手差异、对称循环、全胜数值收敛、最新判断、断组和发题；合成浏览器用例覆盖桌面/手机、范围切换、组间补比较、刷新恢复、清空与存储失败，并确认不产生正式写入。具体本次检查结果以对应 PR 为准，不把本机合成回归称为上线验收。


## V4 数值收敛与名次表达（2026-09-26）

旧实现把任一聚类重采样在 500 次内未收敛，与区间宽或上限敏感共用“结果不稳定”。稀疏宽池中模型目标仍合理，但有限迭代会提前停止；200 次重采样的种子又包含截止点与窗口标签，相同有效输入也会出现不同区间和资格状态。

保留正则化加权 Bradley–Terry、K=50/L=1、先验 0.5、所有入榜门槛与 70/30 综合规则。对手难度适合用批量成对模型处理；改用按顺序更新的 Elo 会新增顺序依赖，换 Glicko/TrueSkill 则需另定动态与不确定性假设，不能直接修复此处的计算停止问题。单纯降低门槛或忽略失败重采样会把计算问题变成虚假精度，因此不采用。

预编译稀疏边并使用 NumPy 执行同一 MM 更新，重采样与对照从基础解开始，最大迭代数增至 5,000，同时检查 log 强度变化与归一化似然梯度残差。默认 1,000 次按标识重采样，种子由有效对位、权重、模型版本与参照池派生；相同输入跨窗口或截止点保持一致。每次拟合保存收敛、次数及残差诊断，任一必需拟合仍失败就不发布区间或名次，基础拟合失败也不发布分数；没有均匀对位的对象不制造纯先验策略对照。

排名范围条件于本次固定合格集合，按相同竞争排名计算重采样百分位；不是全池同时置信集合。前端以小字显示“可能第 X–Y 位”，状态使用“还需更多投票”“排名未稳”“计分影响较大”“统计未完成”。三个榜按随机、厨力、综合排列，新会话默认随机，已有选择保留，不增加表格列或突出警告块。

算法版本升为 bt-dual-scope-v4，迭代参数进入版本摘要，所有新增字段使用原 JSON 快照结构。无数据库迁移，不更新原票据、支持、本命、选择或额度，也不覆盖旧快照；普通汇总创建新序列，趋势沿用跨算法断线。代价是增加 NumPy 运行时依赖及重采样计算量，计算继续在控制锁事务外执行。

三个 624 对象/321 标识/18,036 判断的合成数据集各 1,000 次重采样全部完成；额外 2,000 次对照检查耗时和蒙特卡洛差异。具体结果与覆盖限制见[统计说明](../../../../docs/PREFERENCES_STATISTICS.md#v4-宽池数值检查2026-09-26)。新增求解器、失败隔离、同输入一致、固定排名池及数据库记录保留回归，浏览器检查覆盖四视口和旧快照状态。测试不写业务数据库，线上效果须在部署后的新快照中观察。

## 半小时汇总与资源开销（2026-09-26）

拟合末尾两次短向量点积会唤醒 BLAS 线程，线程忙等使 CPU 时间远高于实际计算收益。改用 NumPy 逐项乘积归约，容器同时将 OpenBLAS/OMP/MKL 默认线程数设为 1；只影响诊断目标值的求和顺序，不改变 MM 更新、收敛条件、分数或区间，因此保持 V4 版本。无需额外引入 threadpoolctl 或减少重采样精度。

同一轮、同一视图的全部原始输入都严格晚于 28 天起点时，84/28 天输入相同，计算一次后深拷贝并修正窗口元数据。包含跳过、不熟悉和边界记录；判定保守，不按投影后的有效票数猜测相同。人物与形态仍独立计算。跨轮持久缓存需正确处理窗口老化、风险审核、名录、版本和无效输入带来的展示变化，当前暂不引入；数据跨过 28 天后会恢复两窗口独立拟合。

汇总周期由 15 分钟改为 30 分钟，所有榜种以两倍周期判定时间延迟；名录、算法、修订变化仍立即过期。应用设置用于新鲜度判断，宿主机 timer 必须单独改为每小时整点和半点，并清空旧 OnCalendar、取消随机延迟，保留服务与维护锁。整点和半点是开始时间，成功发布仍有计算耗时。聚合命令额外记录 wall/process CPU 时间，供部署后比较。

趋势原先遍历 QuerySet 时会提前物化整个历史的 JSON 明细。现在流式读取日期与口径元数据，选出原规则下的 180 个节点再读取完整快照；保留 UTC 日期、同日口径变化和 7/28 天基线规则。仍需扫描元数据与提取 JSON 参照字段，未声称查询成本恒定，也未增加索引或改变旧快照结构。

单视图相同双窗口的完整 1,000 次重采样合成对照从 89.925 秒降至 43.763 秒，进程 CPU 从 336.584 秒降至 41.232 秒；除约 2e-12 的目标值诊断差异，完整结果一致。范围及限制见[统计说明](../../../../docs/PREFERENCES_STATISTICS.md#半小时汇总与性能优化2026-09-26)。make check 通过，后端 223 项（SQLite 跳过 15 项 PostgreSQL 专属检查）；新测试覆盖窗口独立性、原始数据保留、历史筛选语义和新鲜度。PostgreSQL 与容器结果以本次 PR 检查为准，未部署业务服务器。
