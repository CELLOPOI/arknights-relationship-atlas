# 来源标题作为读取时的辅助索引

Status: implemented
Date: 2026-09-21

关系出处原先直接展示解包脚本和档案定位符，读者难以识别具体剧情。用户要求补齐特殊玩法配置、结合 PRTS 核实，并修改网站展示。已有数据库发布流程要求保持正式证据、稳定 ID、方向和条件叙事边界。

后端在公开关系详情读取时，通过随代码交付的名称索引补充 `title` 及经核对的 PRTS 链接；图谱、关系档案、游戏共用这些字段。原始来源、行号、版本完整返回并可展开。索引有游戏提交、输入摘要及逐条依据；未知来源和明确不同版本回退到原始字符串。无版本的既有引用按已核对基线定位，不把它们伪造为已经声明版本的证据。

直接批量改写数据库的优势是让标题随每条证据维护，但会把展示补全变成正式资料发布，且容易混淆原始路径与可读名称。仅在前端打包词典可以少改接口，但重复传送完整词典并使三个展示入口自行处理版本。选择后端只读解析，保持当前发布摘要和原始资料不变，代价是新增来源与游戏版本需同步维护辅助索引。日常构建无须相邻解包工程，索引更新才需要明确输入。

教程和任务片段没有独立剧情名时，使用配置中的关卡或任务名及定位说明；不编造官方标题。15-17 两个分支保留 SIDE:ACCEPT 与 SIDE:REJECT 区别，梗概和正文分开。原始关系证据和条件叙事分类不因补充标题而改变。

适用范围和维护、验证入口集中于 [SOURCE_TITLES.md](../../../../docs/SOURCE_TITLES.md)。该决定补充[后台正式发布决定](2026-09-21-editorial-publication.md)，不替代其数据权限或受控发布规则。生产部署与业务数据库实时覆盖须单独核验，不能由初始化基线覆盖率推断。
