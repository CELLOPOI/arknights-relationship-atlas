# NPC 复核结果作为网站派生导入包

Status: implemented
Date: 2026-09-20

日常正式资料已改为后台修订与受控发布，见[现行发布决定](2026-09-21-editorial-publication.md)；此前 Git 方案保留为历史记录。本记录的来源核验、身份和条件叙事边界继续有效；直接导入已不作为日常正式写入口，上游生成结果须先形成候选差异。既有业务库切换仍需按新发布流程执行。

用户完成重点 NPC 人工复核后，网站需要同时接入人物、方向明确的关系和真实头像；原资料工程及人工意见须保持可追溯，已有干员关系也有独立来源。

决定在网站仓库生成 `data/npc/`，读取相邻资料工程但不回写。导出必须核对人工意见指纹与原文哈希，身份判断限定于有明确引文的场景，条件叙事不混入实际叙事。同一新增人物对按独立知晓方向合并，已有关系保留判定与证据，将重合贡献另存来源文件。头像从已标注的 PRTS 立绘派生，保存原图、输出哈希和裁切范围，通用立绘在界面说明。

直接改写原审读汇总可减少一份派生文件，但会把人工意见、网站既有结论和显示归类混为同一修改历史；直接覆盖旧边可马上统一数量，但会丢失两个资料来源的判定边界。因此保留来源清单和6对方向差异，后续涉及既有干员关系的修订须同时核对两套证据。代价是网站导出依赖相邻资料工程及故事解析器，并维护一份显式 NPC 归类／裁切配置。

当上游有新的复核版本、人物转为正式干员或头像变更时，重新核对身份映射、意见指纹和来源差异，再预演导入。不能仅因下载地址仍可用就接受变更的原图。

实施入口与事实集中维护在 [NPC 接入说明](../../../../docs/NPC_IMPORT.md)，包含来源规则、初始化限制与验证要求。生成器 `scripts/build-npc-data.mjs` 已链接该说明；旧分区与图谱语义约束继续适用。
