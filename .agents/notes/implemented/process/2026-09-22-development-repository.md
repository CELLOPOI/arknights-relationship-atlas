# 开发仓库的职责与提交边界

Status: implemented
Date: 2026-09-22

开发者需要从克隆获得可校验的构建输入，并通过代码、资料规范和测试理解应用。个人连接信息、运行记录、采购与维护流程不能成为源码、历史或协作记录的一部分。

仓库维护前后端、资料初始化与后台发布、通用容器契约、固定素材及开发验证。应用的反馈处理、就绪接口与安全日志属于功能；个人 SSH 发布、备份、监控工具及其运行状态在仓库外管理。文档保存现行规范、复验方式及仍有效的工程取舍。具体文件范围和提交检查集中维护于[仓库约定](../../../../docs/REPOSITORY_POLICY.md)。

固定素材随源码提供，以清单限定文件范围；其他本地版本、资源归档和构建输出不进入提交。另行分发素材能缩小源码仓库，但会使克隆和 CI 缺少构建输入，因此保留固定版本，代价是增加约 164 MiB 素材。资源频繁更新或体量明显增长时再评估存储方式，始终保持确定性校验。素材来源、摘要、版权及许可链接继续保留，`unreviewed` 状态及第三方权利范围不因提交安排改变。

仅把真实部署值换成占位符仍会增加个人运维工具的维护负担，因此仓库只保留通用运行契约。提交前检查暂存区全部差异，并检查提交信息、PR、Issue 和附件；示例采用回环地址或保留示例值。删除文件与忽略规则不清除历史；历史清理后不得通过合并旧历史重新引入已移除内容。

开发验证入口为 `make install`、`make check` 和专用数据库上的 `make check-postgres`；提交边界检查与功能验证分别执行。实际执行结果记录在相应变更的检查结果中，不把个人环境状态写入长期规范。
