# 仓库文件约定

仓库保存开发者审查、构建和验证所需的源文件、资料基线、固定素材及文档。个人运维资料、凭据和应用运行数据留在公开项目之外。

范围与取舍见[工程决定](../.agents/notes/implemented/process/2026-09-22-development-repository.md)。

| 文件类别 | 处理方式与用途 |
| --- | --- |
| `frontend/`、`backend/` 源码、迁移和测试 | 提交，维护应用行为与数据结构 |
| 锁文件、运行版本文件、Makefile | 提交，固定开发与检查入口 |
| 通用 Dockerfile、`compose.yaml`、`deploy/Caddyfile` | 提交，说明容器构建和服务契约 |
| 开发与数据文档、有效工程决定 | 提交，保存可复核的行为和约束 |
| 资料与验证工具、来源及素材清单 | 提交，支持校验与来源追踪 |
| `data/source/`、`data/npc/` | 提交初始化基线、来源及单向资料归档，不含反馈、联系方式或账号 |
| `assets/local/atlas-assets-24d6e8427efd2e90f29f1b7e/` | 仅提交当前清单对应的 2,426 个文件，支持克隆后完整构建 |
| `assets/preferences/`、`data/preferences/` | 喜好扩展固定素材与待审核名录，按独立清单校验；复制文件不自动发布 |
| 其他 `assets/local/` 版本、资源压缩归档 | 忽略，避免无关版本和重复输入 |
| `node_modules/`、`.venv/`、`frontend/public/`、`frontend/build/`、`backend/staticfiles/` | 忽略，由安装或构建生成 |
| `.runtime/`、数据库、反馈、邮件、备份、日志与缓存 | 忽略，包含运行状态或私有信息 |
| 个人服务器配置、访问方式、运维手册与运行状态 | 不纳入公开项目 |
| `.impeccable/`、批量截图和验收输出 | 本地保留，文档只记录可复核的结论 |
| `.env` 及环境变体 | 忽略，只提交不含真实凭据的 `.env.example` |
| 历史 `dist/`、旧部署配置 | 不纳入日常开发输入或源码提交 |

`make check` 使用随库资料和固定素材。`make test-upstream` 有额外的上游和历史输入要求，不是日常开发的前置步骤。素材更新须同时核对清单和 Git 跟踪范围，流程见[素材说明](RESOURCE_PACK.md)。来源、版权及许可文件须保留；素材随仓库提供不改变 `unreviewed` 状态或第三方权利范围。

截图和日志等验证输出默认写入 `.runtime/verification/`。共同审查时只选取经隐私检查的必要附件，不提交整批截图、日志或数据库。文档保存现行开发契约、复验命令和必要工程取舍，不积累阶段报告、个人操作流水或过时状态看板。

## 提交前检查

每次提交前逐项查看暂存文件和完整差异，不以工作区检查代替暂存区检查：

```bash
git diff --cached --name-status
git diff --cached
git diff --cached --check
```

确认新增、修改、重命名及删除都属于本次开发范围，再检查以下内容：

- 不含个人主机名、真实 IP、SSH 连接方式、个人绝对路径、备份位置与标识、告警标识、凭据、订单、真实反馈或联系方式。
- 示例使用回环地址、保留示例域名和明确的占位值；测试数据使用虚构内容。私有资料保存在仓库之外，不能只改名后提交。
- 素材仅纳入固定清单列出的文件，同时保留来源、校验和许可记录；不无差别加入整个本地素材目录。
- 提交信息、PR 正文、Issue 及附件同样逐项检查，不复制未经处理的终端日志、截图或运维记录。
- 检查 Git 作者与提交者信息，公开提交使用与账号对应的 noreply 邮箱，保留准确署名，避免把个人邮箱写入历史。

忽略规则不会停止跟踪已有文件；删除文件和添加 `.gitignore` 都不会清除历史提交。发现历史中的私有内容时须单独处理历史与相关公开记录；清理后以新的仓库历史为准，不得合并旧分支或旧克隆的历史重新引入已移除内容。文件边界、凭据检查与干净构建分别验证，任一项通过都不能替代其余检查。
