# 匿名反馈（FEEDBACK-01）

反馈使用独立私有队列，不需要注册，不受 `COMMUNITY_ENABLED` 控制。先调用 `GET /api/session/` 获取 CSRF cookie；`feedbackEnabled: true` 表示反馈入口可用。提交使用 `POST /api/feedback/`、`Content-Type: application/json` 和 `X-CSRFToken`，携带同源 cookie。服务端对匿名请求也执行 CSRF 检查，并拒绝跨源 Origin。

网站 `/sources/` 的“反馈来源或版权问题”也使用同一私有队列，默认选择 `source` 类型，不预设人物或关系目标。资料页与游戏页继续使用原有入口；该页面没有新增上传、公开列表或自动发 Issue 功能。

| 字段 | 约束 |
| --- | --- |
| `type` | 必填：`data_error` 资料纠错、`source` 来源补充、`addition` 资料补充、`site_issue` 网站问题、`other` 其他 |
| `description` | 必填非空文本，最多 6000 字 |
| `targetType`、`targetId` | 可选，必须同时提供；类型为 `person` 或 `relationship`，ID 最多 220 字，目标必须已公开 |
| `sourceUrl` | 可选，最多 1500 字，仅无账号密码的 HTTP/HTTPS URL；服务器不抓取链接 |
| `contact` | 可选纯文本，最多 254 字，用于维护者需要时联系补充信息 |
| `website` | 隐藏的防垃圾字段，正常访问者留空；非空请求返回收件确认但不入队 |

仅接受声明字段，文本字段不接受数字或对象。请求体最多 32 KiB，仅接受 JSON，不接收附件，也不执行富文本。正常接收和短期重复提交均返回 HTTP 202 与 `{"detail":"反馈已收到，维护者会核查。"}`，不返回可枚举 ID。错误包括字段或 JSON 无效 400、CSRF/跨源 403、未知或未公开目标 404、正文过大 413、媒体类型不支持 415、频率超过限制 429（含 `Retry-After`）。CSRF 错误可能是 Django HTML 页面，客户端须处理非 JSON 错误。没有公开反馈列表或详情路由。

每个来源标识每小时允许 5 次有效提交；24 小时内同一来源、相同规范化字段内容只生成一条反馈，重复请求仍计入次数。限流与去重使用数据库记录和事务行锁，支持多个服务进程；不依赖进程内缓存。频率限制不代替反向代理的请求体、连接数和流量防护。

防滥用记录仅保存以 Django 密钥生成的 HMAC，不存原始 IP、不关联反馈 ID，过期时间为最后一次计数后 24 小时；去重摘要保留 24 小时。默认以 `REMOTE_ADDR` 为来源，不信任客户端转发头。反向代理部署时，使用 `FEEDBACK_TRUSTED_PROXY_IPS` 配置可信直连代理 IP（逗号分隔），只对这些代理采用其追加的最后一个 `X-Forwarded-For` 地址。须保证应用端口仅对代理开放、代理覆盖或追加可信的客户端地址；未配置时代理后的访问者共享该代理的限额。当前 Compose 的代理地址需在部署时核实，不能直接信任任意转发头。

后台入口为 `/admin/atlas/feedback/`。维护者须具备 staff 身份及 `atlas.view_feedback` 或 `atlas.change_feedback` 权限；没有该权限的后台账号看不到队列。`atlas.change_feedback` 允许更新待处理、已关联 Issue/PR、重复、已解决或不采纳状态。离开待处理状态须写明理由，已关联状态须提供 HTTP/HTTPS Issue 或 PR 链接。系统记录处理人、时间及每次处理字段变化；陈旧页面保存显示冲突，不能覆盖其他维护者的处理。原始反馈只读，不提供手动新增、删除或批量处理动作。

联系方式额外要求 `atlas.view_feedback_contact` 权限，不进入列表搜索或处理审计。反馈、联系方式、内部备注和处理记录均不属于正式资料导出；本功能不向 GitHub 发送消息或创建 Issue/PR。维护者应核实并手动整理公开资料，不能直接复制联系方式或私有备注。

保留规则：联系方式在收件 90 天后清空；反馈及其处理记录在收件 365 天后删除；短期防滥用记录到期后删除。原文中由访客自行填写的联系方式仍随反馈原文保留至反馈删除。部署须定时执行 `python manage.py purge_feedback`，建议每小时一次；实际删除时间受执行间隔影响。可用 `--now 2026-09-20T00:00:00+00:00` 在专用测试库验证过期边界，生产不要用未来时间提前清理。备份中的私有数据另按部署备份保留策略清理。本地实现没有创建服务器定时任务。

前端应明确说明：“反馈仅供维护者核查，不公开展示。联系方式可不填，仅用于补充询问，90 天后清理；反馈内容最多保留 365 天。请勿提交敏感个人信息。” GitHub Issues 仍是主要公开反馈入口。

回归覆盖有效匿名提交、严格字段和目标、正文与媒体限制、真实 CSRF、独立社区权限、数据库限流和去重、不可枚举读取、后台与联系方式权限、处理审计、陈旧保存及过期清理。`test_feedback_concurrency.py` 的三项竞争测试只在 PostgreSQL 执行，SQLite 结果不能代替行锁验收。

## 关联资料修订

具有资料修订及反馈处理权限的维护者，可从反馈详情创建修订。页面展示关联修订及状态；发布者预览时核对当前反馈状态，确认发布后在同一事务中结案，并保留处理历史。反馈在预览后被其他维护者修改时拒绝发布，须重新核对；资料回退不自动改判历史反馈。后台不会把联系方式或内部备注复制进正式资料。
