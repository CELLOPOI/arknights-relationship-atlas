# 后台资料维护

2026-09-21 起，日常资料维护使用 Django 后台的“资料修订 → 审核 → 预览发布”。正式依据为数据库中的已发布版本。代码继续通过 Git PR 维护；Git 中的资料用于初始化和已发布快照归档，不与后台双向覆盖。该决定替代 2026-09-20 的“每次资料修改都提交 PR”，保留稳定 ID、方向、原文、条件叙事隔离及受控发布。

## 编辑与审核

1. 登录 `/admin/`，进入“资料修订”，填写标题及修改说明。也可以在“访客反馈”详情中选择“根据此反馈创建资料修订”。
2. 添加现有人物、阵营、身份映射、关系或独立证据；留空“已有资料”可新增。人物、关系及其证据可以放在同一个修订内，并引用本次修订中的新条目。身份映射须填写实际游戏角色 ID，其他新增条目可以生成 ID。
3. 编辑字段、原文及逐条来源，保存后返回修订。条目可以分步填写；提交前必须补齐引用和证据。原文保留换行，来源可填写起止行和版本。已存在的关系不能改变端点，已有证据不能转挂到另一关系。
4. 核对逐字段差异和关系原文，点击“提交审核”。提交会验证整个资料版本、公开证据、知晓方向和头像资源，未通过时仍保留草稿。
5. 审核者填写意见后通过或退回。待审核和已通过内容禁止继续编辑；修改须先退回草稿，之前的审核和发布预览随之失效。人员较少时同一维护者可以兼任角色，系统如实记录每一步的操作者，不声称进行了独立复核。
6. 发布者点击“预览发布”，核对内容及关联反馈状态，再确认发布。正式资料、发布记录、修订状态和反馈结案在同一事务内提交。任一步失败全部回滚。

“移出本次修订”保留条目和历史，只取消本次应用。撤下正式资料请修改其“已公开”字段，不删除稳定 ID。整批取消只适用于草稿。

## 版本冲突

每次表单保存核对条目版本与整个修订版本。发布状态、修订、条目、反馈按固定顺序加锁；两人提交旧页面时不会覆盖新修改。

如果别的修订先发布，当前修订须退回草稿并“更新修订基线”。未被其他发布修改的条目可以继续使用；冲突条目须先移出，再更新基线，从最新资料重新添加并核对。恢复跨基线的已移出条目时采用新基线，旧内容仍在条目历史中。每次变更后重新审核。

发布预览绑定修订版本、完整资料摘要、当前正式版本、素材版本、发布账号及关联反馈的版本，有效期一小时。内容、基线、素材或反馈变化后重新预览。反馈结案也需要查看及处理反馈权限。

## 权限

账号必须是有效 staff；通过 Django 的用户/组页面分配权限。无需给每位编辑超级管理员权限。

| 职责 | 权限 |
| --- | --- |
| 编辑 | `view/add/change_changeset`、`view/add/change_candidate`，以及所需正式资料的只读权限 |
| 审核 | `view_changeset`、`review_changeset`、`view_candidate` |
| 发布 | `view_changeset`、`publish_changeset`、`view_datarelease` |
| 从反馈创建修订或发布关联修订 | 在上述权限外增加 `view_feedback`、`change_feedback` |
| 查看联系方式 | 另行授予 `view_feedback_contact`；普通编辑、审核和发布不需要 |

表中权限均属于 `atlas`。公开接口不能读取修订、反馈及操作记录，所有后台写操作验证 CSRF。正式资料表继续只读，旧导入和社区入口继续关闭。

## 发布、回退与归档

“资料发布”保存不可编辑的版本快照、前版和发布人。选择一个历史版本可创建回退修订，查看差异、审核并发布为新版本。回退保留后来新增的稳定 ID，将可撤下记录设为不公开；不会恢复整库或删除后来收到的反馈、账号和审计。关联反馈的既有处理记录不会因资料回退被自动改判。

“导出此版本资料快照”下载符合现有 schema 的确定性 ZIP，包含正式人物、关系、独立证据、条件叙事和来源记录；元数据记录发布 ID、资料摘要、素材版本及来源。包含显式撤下记录，以保留引用。账号、反馈、联系方式、内部备注和审核意见不导出。可以解压到独立目录并运行 `compile_source` 核验，或作为单向 Git 归档提交；不要反向覆盖网站。

旧独立候选通过“创建修订并加入此候选”接入本流程，原候选内容和编辑历史保留。独立候选导出仅用于备份，关联候选须整批审核；公开快照从发布版本导出。

## 初始化与升级

首次部署仍须先核对业务资料并建立第一个发布基线，见 [发布与回退](DATA_RELEASES.md)。迁移 `0008_editorial_workflow` 只新增修订相关结构及来源状态，不改判现有关系，不发布草稿，也不转换旧候选内容。

第一次后台发布将权威来源置为数据库，此后旧 Git 资料包的预览与应用均拒绝执行。应用升级只迁移结构并更新代码，保留数据库里的正式版本；交付目录内的初始资料包不作为升级时的覆盖输入。新增素材仍随固定资源包和代码交付。若只更新素材版本，也可创建不含条目的修订，填写依据后审核、预览并发布；资料内容不变，服务端仍校验全部公开头像引用。

条件叙事与上游贡献始终与实际关系分开保存、快照导出和回退；当前字段编辑界面覆盖人物、阵营、身份、关系、证据，未提供条件叙事或上游批次的可视化编辑器。

验收命令与本轮结果见 [后台更新验收](EDITORIAL_VALIDATION.md)，架构取舍见 [后台发布决定](../.agents/notes/implemented/architecture/2026-09-21-editorial-publication.md)。
