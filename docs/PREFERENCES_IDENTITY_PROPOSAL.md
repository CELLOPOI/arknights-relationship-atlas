# 人物合并与异格独立人气方案

状态：已按用户确认实施，代码与本地验证完成，未部署线上。随机题一次采集，随机榜、支持榜及综合榜均提供形态与人物两种视图。数据库升级使用 `0011_preference_identity_scopes`。

采用一次采集、两种统计视图：用户只比较眼前的干员形态，不选择计票口径；结果默认“干员分开”，也可切换“人物合并”。例如斯卡蒂、浊心斯卡蒂在分开榜各占一行，合并榜只有斯卡蒂。

已确认的产品预设：偏好某个形态的判断，同时代表对其所属人物整体的偏好。该预设用于人物合并榜；形态分开榜仍只采用实际出场形态的判断，未出场的其他形态不凭空增加胜负，否则无法区分各异格的人气。此决定替代原提案的两套随机题入口，已落实到任务、支持登记、统计快照与结果界面。

## 身份与展示

| 层级 | 含义 | 示例 |
| --- | --- | --- |
| `person_id` | 剧情中的同一个人，沿用正式资料稳定 ID | 斯卡蒂 |
| `form_id` | 本体、异格或明确职业形态 | 斯卡蒂、浊心斯卡蒂；阿米娅的职业形态 |
| `appearance_id` | 对应形态的基础、精二或服饰 | 某一套立绘 |

NPC 没有干员形态时，在分开榜使用带类型的 `person:<id>` 单例对象，不虚构游戏形态。普通干员使用 `form:<id>`，即使其原始字符串恰好与人物 ID 相同也不会混淆。临时支援实例经明确映射归到其对应形态；不能按名字、图片相似或统一 `person_id` 删除真实异格。

本次皮肤目录将暮落、Sharp、Pith、Touch、Stormeye、郁金香的六个临时实例归并为单一入口，底层 446 个来源形态与历史链接保留，目录展示 440 项。领主·Sharp 及阿米娅职业形态仍各有入口。新的人气对象池同样排除这六个来源实例，只保留规范形态；原有皮肤与同人形态偏好登记仍按原 ID 保存，不转挂历史票。

## 支持与本命

保留“最多支持 15 个人物”的额度，用户直接勾选形态，多形态仍占一个人物名额。每个形态每个匿名参与标识最多贡献 1，后台自动按所属人物去重生成合并支持。界面显示已选形态与占用的人物名额，不要求用户分别填写两份支持名单；沿用当前冷却和对象版本规则。

例如同一个标识支持斯卡蒂和浊心斯卡蒂：两张形态卡各增加 1，合并斯卡蒂只增加 1。因此合并人数是参与标识的并集，不能把两个数字相加。取消其中一个形态仍保留人物支持；取消最后一个形态时自动取消由形态派生的人物支持，不追加确认问题。历史上未指定形态的人物支持单独保留，直到用户撤回，不复制给各形态。

本命仍最多 3 个人物，并且必须已支持。用户直接把一个已支持形态标为本命，后台同步其人物本命；同一人物最多一个形态本命，改选自动替换，不要求再次选择人物。历史未指定形态的本命继续保留。人物本命每标识仍计 1，本命保留为分项，不给综合榜额外加分。

## 随机好感与综合榜

随机题只有一个入口，直接展示两个不同人物的具体形态，用户选择更喜欢的一方。形态图使用固定代表图，私人皮肤选择不改变题面。只有结果页提供“干员分开 / 人物合并”切换；统计说明简述“人物榜合并本体与异格的选择”，无需用户在每题理解统计规则。

每题只保存一份原始回答，同时保留双方实际形态 ID、所属人物 ID、胜方、名录与素材版本。统计时从原始回答生成两种观察：

| 原始回答 | 干员分开 | 人物合并 |
| --- | --- | --- |
| 浊心斯卡蒂胜过缄默德克萨斯 | 浊心斯卡蒂胜、缄默德克萨斯负 | 斯卡蒂胜、德克萨斯负 |

双方都要映射，胜负对称处理；不只传播胜利而忽略对方的落败。这个结果不会给未出场的本体斯卡蒂、本体德克萨斯追加形态胜负。原有同人内部形态偏好、皮肤选择和练习仍不转成随机票或厨力支持。

形态榜按“参与标识 + 无序形态对”保留窗口内最新有效明确判断。人物榜先将原始回答映射为人物对，再按“参与标识 + 无序人物对”去重，之后重新计算贡献权重并拟合；不能先计算各形态分数再相加、平均或取最高。一个标识先后比较斯卡蒂与德克萨斯的不同形态，形态榜各保留相应判断，人物榜只保留该人物对最新的一次；若判断相反，也采用最新明确判断，不挑对某方有利的结果。跳过不覆盖已有明确判断。

随机抽样先选两个不同人物，再各选一个合格形态。均匀抽样以人物为单位，补样策略也先分配人物曝光预算；不因形态数量增加人物的总抽中权重。同人内部比较沿用原形态偏好入口。各形态共享人物曝光预算，样本会被摊薄，须显示各自样本量并继续执行冷启动门槛；新增形态不继承同人的既有形态成绩。

每题只消耗一次周额度和滚动额度，曝光上限按所属人物计算。统计中的 K/L 贡献上限分别在各视图完成去重后计算；人物榜的 L 约束整个所属人物，不能给每个异格各领一份人物贡献额度。两种结果独立拟合、检查资格并保存快照，同一回答分别用于两种视图不等于在人物榜重复计票。

综合榜沿用现有“随机好感 70% + 当前支持 30%”的百分位方案，但参照集合、资格和支持人数分别按人物、形态计算。两个榜的 80 分不宣称可直接比较。形态池没有足够随机样本时只展示支持等有效分项，综合名次显示“样本积累中”。

人物榜表示本站约定下的“各形态选择合并结果”，不是额外采集的一份人物总体问卷。受欢迎的新异格可能提高所属人物的合并成绩，这是已接受的产品含义。曝光预算、去重与贡献上限用于避免单纯按形态数量多算票，不保证人物分数不受形态阵容或实际展示分布影响。

## 数据与迁移

- 保留现有正式人物和形态 ID。新增可审读的统计对象类型及临时实例归属映射，并绑定名录版本。
- 新随机任务记录实际展示形态及当时所属人物，保留原始回答来源；历史任务标记为人物口径，不把同一题复制成两份业务票据。新任务的防重复键采用形态对，人物曝光上限继续按人物计算；待答唯一约束仍按参与标识控制。查询、缓存和快照用 `scope` 区分统计视图。
- 增加参与标识与规范形态之间的当前支持状态及事件历史，明确区分历史未指定形态支持与新形态派生支持。修改形态支持及人物去重结果在同一事务内完成；用户可以逐项移除或保存空名单撤回全部；取消最后一个形态时自动移除派生贡献，历史未指定形态支持仍按自己的撤回状态处理。
- 历史人物支持与本命保留，不分摊给本体，也不复制给每个异格。已有皮肤登记和“偏好哪个形态”也不推导为新增支持。
- 旧随机票、趋势和快照保留为人物口径。旧票未记录明确形态时不猜测分配；形态榜只使用新采集。人物新快照可将窗口内合格旧人物票与新回答的人物映射合并，再统一去重和封顶；不得同时纳入新回答及其重复副本。采集语义变化记录新算法版本与趋势断点，不与旧快照直接连线。

实现入口为 `preference_subjects.py`、`preference_services.py`、`preference_statistics.py` 与人物/结果视图。`test_preference_identity.py` 覆盖两侧映射、未出场形态不增票、跨形态最新判断去重、人物曝光、支持并集与撤回、旧票保留、快照和趋势隔离；包含旧 schema 实际升级与 20 个合成参与标识、6 个人物、各 1–3 形态的去重/贡献上限检查。桌面和手机真实 API 流程验证题面恢复、实际形态记录、同人支持名额、本命替换、旧登记保留及榜单切换。验证证据见[运行说明](PREFERENCES.md#复验)。新形态池的区间覆盖、连通性、冷启动速度及真实展示分布仍需公开试运行评估，旧 V2 模拟不代表双榜已完成统计校准。

分别采集人物题与形态题能明确区分两种问题，但增加用户判断和参与成本，因此按已确认预设改为单次采集。直接把胜负复制给同人所有形态会制造未出场判断，掩盖异格差异；直接相加各形态得分又绕过人物去重和贡献上限。因此采用“一份原始回答，形态直接统计，人物映射后重算”的方案。
