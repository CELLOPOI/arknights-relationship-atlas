# 人物连线：四种模式

Status: implemented
Date: 2026-09-20
Updated: 2026-09-21

入口为顶部 `GAME / 游戏` 与 `/game/`。游戏独立挂载 Vue 页面，使用现有 `/api/graph/?scope=all` 正式资料、本地人物头像与完整构图立绘。代码位于 `frontend/src/game/`，不改写数据库中的关系判定。

页面提供“普通模式”“六步探索”“输入挑战”“双人判断”。新访客默认进入普通模式；有旧六步存档的访客继续原题。四种模式共用原来的左右人物立绘、灰色背景特写和精一／精二交换，只替换中间玩法。每种模式独立保存规则与进度。

## 规则与操作

- 用户明确指定“有连线就算，不管相识种类”。相识、单向知晓及其原始方向均不影响游戏通行；每条已收录连线可以双向走一步。
- 默认禁用博士、阿米娅、凯尔希。规则面板支持按名字、真名、异格及阵营搜索，自定义添加、删除禁用人物，也可恢复默认三人或清空。禁用对起点、终点、中转统一生效。
- 四种模式默认使用“仅干员”范围，可以切换“干员与 NPC”。旧存档中明确保存的范围保留。异格可以使用独立名称与立绘出场，但沿用正式人物身份，不创建额外关系节点；禁用及同一路线的重复判定同时覆盖本体和异格。
- 六步探索与输入挑战最多走六条边，同一路线不能重复经过人物。六步探索继续显示当前人物的全部未经过、未禁用邻居，支持搜索，列表内部滚动，不截断可走人物；输入挑战由玩家自行填写下一位人物。
- 六步探索和输入挑战的入门题最短距离为两步，标准题三至四步，挑战题五至六步。全部难度都有六步额度，允许任意有效路线通关。普通模式的难度按空位数区分，见下文。
- 撤回释放当前路线的一步，同时保留探索选择次数。提示给出当前路线下一位可行人物，同一段路线重复请求同一个提示只计一次；当前走法不能在剩余额度内到达时，提示撤回。
- 走满六步仍未抵达显示失败，可撤回调整。主动查看答案会结束本局，不能继续以已揭晓的路线计为通关；可以重试本题或开始下一题。
- 结算显示当前路线步数、最短步数、探索次数和提示次数。答案默认显示一条，可展开其他有效路线，每段关系均可查阅现有证据 API 的原文与来源。

规则面板编辑的是草稿。关闭会丢弃草稿；应用规则时先检查是否能出题，成功后才替换当前题目。没有符合难度的路线或抽题池不足时显示原因，保留原题与原规则。

## 双人判断：直接认识或找中间人

从当前范围与禁用过滤后的人物池抽出两位人物，先判断是否有直接连线。有线叫“认识”，没线叫“不认识”；关系种类、单向知晓方向不影响第一步答案。这是用户指定的游戏口径，原档案的相识／知晓分类与方向保持不变。

每轮 10 题，其中 5 对直接相连、5 对不直接相连但可通过一人接通，出题顺序和左右人物顺序均打乱。同一轮不会重复同一人物对，也不会将本体与异格抽成两个人。每类题池都足够时避开上一轮人物对；不足以各抽 5 对时拒绝应用该规则，不改变比例或重复凑题。相距三步以上或处于不同连通分量的两人不用于此模式，避免第二步无解。

点击“认识”或“不认识”立即提交第一步，不另设确认按钮。两个选项保留在原位并锁定；所选答案正确时显示浅绿文字、细框和暗绿底，错误时沿用柔和红色及暗红底，并配有“正确／错误”文字。直接相连的题随即结算，可查看真实关系原文；不直接相连的题展开中间人候选池，即使第一步答错也可继续选人。候选通常 6 人，抽取至多 2 位共同邻居，其余从非共同邻居中抽取；只有一位可用中间人时放入一位正确候选，小人物池允许不足 6 个选项。候选不包含两端或禁用人物，任何同时连接两端的候选都有效。

点击候选只选择，不展示其两侧关系。确认中间人后锁定作答，显示是否能连接两人、候选中的有效路线及原文，其他有效候选可展开查看；两步都答对才算答对整题。第一步已提交、第二步尚未提交时，切换模式和刷新仍停留在候选池。完成 10 题显示本轮成绩，可再玩一轮。此模式不使用路径难度、步数、撤回或提示，规则面板显示人物范围、配比与计分说明，以及禁用名单。

`recognition.ts` 分别从直接相连、存在共同邻居的无序人物对中进行蓄水池采样，再打乱题序，不采用直接随机抽两人的方式，以免关系稀疏时大量题目都答“不认识”且没有中间人。遍历人物对时检查邻接与共同邻居，蓄水池只保留本轮所需的人物对；为抽中的间接题建立正确候选与干扰项。`RecognitionPlay.vue` 负责两步作答和结算；左右立绘标为人物 A、人物 B。题单、候选、当前题序、已确认的两步答案和异格形象独立保存，恢复时校验范围、人物对与候选去重、配比、候选有解、答案长度和未完成步骤，分数根据当前关系重新计算。旧的纯二选一题单重新生成，其他模式进度保留。

## 普通模式：补全关系

从有效最短路线中留空：入门为两步路线、一处空位；标准为四步路线、两处空位；挑战为六步路线、三处空位。空位固定交错排列，每处都保留两侧人物，提供最多六位候选，优先混合只连接一侧的人物与有效替代答案。规则过严时候选可以少于六位；没有符合路线长度的题目时保留原题并提示调整规则，不降低空位数。

点击候选只选择人物，不公开其与两侧是否有连线，也不展示关系原文；确认填入后才判定。任何候选只要同时连接两侧、且不与路线中的其他人物重复，就可以填入，并不要求等于生成时的参考答案。选错保留空位并记录作答次数，不指出具体哪一侧不成立。填对的连线可在沿途关系中查看依据，主动揭晓后可查看完整答案原文。

“提示：排除一人”由玩家主动使用，每处空位限一次，只排除一位错误候选并记录提示次数，不给出正确人物或两侧关系判定。如果候选全部有效，则禁用该提示。主动揭晓答案结束本局；重试清空作答与提示。

`completion.ts` 维护留空、候选、判定与恢复。不同空位的候选互斥，避免先填一处占用另一处的唯一解。恢复时拒绝旧的单空标准题和双空挑战题，保留规则后重新出题。当前是按图谱生成的补全题，尚未建立人工精选题库；可玩性需要后续真实玩家反馈。

## 输入挑战：自行填写人物

系统给定起点和终点，玩家逐步输入中转人物或终点；步数、禁用、撤回、提示和通关规则沿用六步探索。页面不显示当前人物的邻居列表。姓名匹配在全体已收录人物中进行，不利用邻接关系排序、隐藏或推荐答案。确认后才检查本局范围、禁用、重复和真实连线；无效连线不消耗步数，文案只说明“暂无已收录连线”，不推断剧情中双方不相识。

`names.ts` 复用 API 的代号、外文名、真名和异格别名，额外维护常用玩家绰号。全半角、大小写、空白、分隔标点和拉丁字母附加符统一处理；支持子串、有限的顺序省略以及三字以上的一次增删改字容错。完整名称唯一匹配时可按回车确认；模糊或重名结果需主动选择，不自动提交第一条。界面展示前八位并提示补充名字；中文输入法组词期间的回车不会提交连线。

常用绰号依据[玩家原始整理](https://www.taptap.cn/moment/464732177255366709)核对，`42` 和 `水陈` 另见 [PRTS-CLI 作者示例](https://github.com/adrzhou/PRTS-CLI)。这些称呼仅用于输入匹配，不写回正式姓名或作为关系依据；异格绰号映射到现有统一人物。当前包含“小羊”“小火龙”“德狗”“42”“水陈”等，不声称覆盖所有玩家称呼。新增有歧义的绰号应保留多个匹配，由玩家确认。

## 异格形象与多条答案

`appearance-catalog.json` 收录当前 38 个异格的角色 ID、名称、外文名及对应正式人物 ID，来源为本地游戏角色表与已核对的正式别名。运行时只启用正式人物仍已公开、且别名仍包含该异格名称的映射。每次新题为这些人物在本体和异格中选择一种出场形象，四种模式均可出现；本局选择随进度保存，切换模式、撤回、重试和刷新不随机换人。双人判断在同一轮内保持各人物的形象一致。

异格共享本体的关系、禁用和已访问状态，不能把本体到异格当作一步，也不能绕过人物禁用。输入异格名称或明确的异格绰号时，匹配结果展示该形象；成功输入中转人物后使用该形象，题目给定终点的形象保持不变。形象复用是游戏规则，不改写数据库或将异格的条件叙事解释为正式关系。

`solutions.ts` 为探索和输入模式按步数递增枚举六步内不重复人物的有效路线，最多返回 12 条参考路线，并限制搜索次数；普通模式只枚举保持已给定人物、且空位答案均来自本题候选的组合。本次补全路线另外保留。界面通过原生可展开区展示其余答案，逐段可查原文；仅有一条时如实说明，不制造替代路线或声称列出所有走法。

## 算法与状态

`network.ts` 先按资料范围和禁用名单构建无向邻接表，边上保留原始关系 ID，供原文查询使用。通过广度优先搜索（BFS）得到最短路径；搜索最多扩展六步。

出题遍历所有剩余人物的有界 BFS 结果，从满足难度的无序人物对中做蓄水池采样，之后随机决定哪一端作为起点。这样不会因有限次数的随机尝试而把稀少的有效题误判为不存在。存在其他题时避开上一题；当前限制只剩一个人物对时允许重复。空间上无需保留整张人物对距离表，出题开销上界为 `O(V × (V + E))`。

提示搜索会进一步排除已经经过的人物，并检查剩余步数。玩家每次操作也会再次检查邻接、重复、六步额度和结束状态，不以显示中的候选按钮作为唯一校验。

`modes.ts` 将当前模式及四份独立进度保存在 `arknights-games-v2`，各模式另存 `appearances` 形象映射。首次读取旧 `arknights-six-links-v1` 时校验并迁移到六步探索，不删除旧记录。恢复时校验人物、每条边、步数、难度，以及普通模式的空位、候选、已填答案和双人判断的整轮题目；缺少或失效的异格映射回退为本体。人物或关系版本与结构形成数据指纹，资料变化后保留各模式规则并重新出题；损坏缓存或不可用存储不会阻止游玩。草稿设置不提前保存。

游戏按需加载，不启动原关系图的全局导航、粒子和画布监听。`/game` 与 `/game/` 均可直接访问，Vite 与现有 Caddy 配置都使用 SPA 回退。完整前端生产构建仍输出到 `frontend/build/`。

## 视觉与验证

沿用现有 `site.css`、`graph.css` 和社区弹层的字体、颜色、细线、直角控件。桌面将立绘放在操作区两侧：左侧跟随当前人物，右侧固定本局终点。左侧在连线、撤回、重试与恢复进度时同步；起点仍保留在路线第一格。规则与沿途关系位于操作区下方。手机竖屏将两幅立绘并排放在路线之上，宽度大于 760px 的矮横屏保留左右布局。候选列表和规则弹层可以分别滚动，原生 dialog 提供模态焦点与 Escape 关闭，支持键盘、触摸和减少动态设置。

四种模式都使用同一个 `CharacterIllustration.vue`，普通模式左侧跟随当前空位的左侧人物；双人判断显示本题的 A、B 人物。模式入口沿用青色下划线，连线题操作区明确展示系统给定的起点与终点。手机保留两幅立绘，候选改为单列；姓名输入与确认按钮允许缩窄，不覆盖立绘切换入口。

### 立绘来源与维护

参考只读工程 `arknights-rebuild` 的 `SectionCharClient.js`、`OperatorStyles.js` 与 `6aed155137c3fe93.css` 中的前景／背景叠层方式。干员默认前景使用精一立绘；没有独立精一图时沿用基础立绘。点击露出的灰色背景或下方“切换精二”可将精二换到彩色前景，再点一次换回。左右两侧独立切换，左侧换人物时恢复精一，右侧在本局探索中保留所选阶段。阶段不写入游戏进度，不改变路线或规则。

两个阶段的背景都使用对应皮肤的官方半身构图，放大为灰色人物特写；禁止把完整全身图直接充当特写备用图。背景略缩小并向外侧分布，彩色前景向内收，精二场景的外侧上角渐隐，为背景脸部留出空间。横向与纵向遮罩将特写融入黑底。NPC 只显示原有剧情立绘，没有精二的干员也只显示前景。小尺寸 NPC 原图限制放大，背景不镜像。

原站 `SectionCharClient.js` 的精英阶段按钮调用 `50610.js` 的 `CommonTransition`，前景与背景分别采用正反横移；对应 `_pretty/6aed155137c3fe93.css:1106–1167` 定义 300ms 单段过渡。游戏沿用相反方向的横移与淡入淡出，将交换并行处理，入场 300ms、退场 180ms。先加载、解码新前景和背景再开始交换；失败时保留当前画面，原入口显示重试。加载或转场中忽略重复点击，换人物后迟到的加载结果不生效。入口支持触摸、Enter、Space 与可见焦点，系统减弱动态时直接交换。

基础图库覆盖 396 位干员、169 位 NPC：396 张基础／精一、357 张完整精二和 169 张 NPC 原图，加上各 357 张精一与精二半身图，共 1,636 张透明 WebP。完整干员立绘来自 [fexli/ArknightsResource 的固定提交](https://github.com/fexli/ArknightsResource/tree/3596def3267fe2b172ba20895b47e11c0523642f/charpack)，提交时间为 2026-09-11 08:03:51 UTC，游戏资源版本为 `26-09-09-07-16-57_d4e461`。使用当前游戏 `skin_table.json` 的 `buildinEvolveMap` 与 `illustId` 匹配完整构图，阿米娅明确使用精一 `1+` 图；背景通过相同皮肤的 `portraitId` 匹配。每个阶段各有 330 张半身图取自同提交的 `charpor`，其余各 27 张取自既有 [ArknightsGameResource 固定版本](https://github.com/yuanyan3060/ArknightsGameResource/tree/57ef5385c1ab1315fe4f2094f399b5c803bd71fc/portrait)，提交日期同为 2026-09-11。

本轮沿用相同固定提交，补齐 38 种异格的 152 张立绘／特写与 38 张头像。现在立绘索引共 603 个形象、1,788 张图；异格来源、皮肤 ID、透明裁切、尺寸和源文件／派生文件摘要记录在 `assets/appearance-manifest.json`。每种异格均具备精一、精二和各自特写，不用本体立绘替代。原有素材保持不变，只有索引增加条目。

上游有 `b` 文件时，完整图库选用同构图的低分辨率版；网页派生图仅去掉透明留白，最长边不超过 1400px，并保留透明度。半身图不在资源生成时放大。页面默认请求精一完整立绘与精二半身特写，点击交换后再请求完整精二与精一半身图。

NPC 原图复用 `.runtime/npc-originals/` 的已验证 PRTS 图片；缓存缺失时从原有来源下载，并检查原图 SHA256。5 位只有通用形象的 NPC 保留“剧情通用立绘”标注。素材包括当前图谱人物的基础／精二、38 种已映射异格与 NPC 立绘，不包含全部皮肤及未收录人物。当前整个资源包的文件数量与大小见[素材包说明](RESOURCE_PACK.md)。

可部署资源位于固定资源包的 `illustrations/`，精简索引为 `index.json`；基础形象的来源、原始尺寸、透明边界裁切和摘要记录在 `assets/illustration-manifest.json`，异格记录见上文。fexli 资源另核对目录树中的 Git blob SHA1。`prepare:assets` 和 Docker 构建从 `assets/local/<清单版本>/` 将文件带入前端，不在启动时访问 GitHub。页面共用一个索引请求，只请求左右当前显示人物的图；图片加载失败显示小头像与重试按钮，仍可继续游戏。更换人物或形象后，延迟完成的旧请求不能替换当前人物。

立绘和中间操作区属于独立的 `.game-stage`，吸附范围在该区域底部终止；规则、关系原文位于其后的独立区域，不能放回吸附立绘共用的多行 Grid。“换一道题”与撤回、提示放在同一操作栏。遮挡回归必须检查整个页面滚动范围内的元素相交和实际按钮点击，不能仅检查页面横向溢出。

验证已安装素材，或在独立目录重新制作异格候选包，在项目根目录执行：

```bash
make assets-verify
node scripts/prepare-game-appearances.mjs --output .runtime/game-appearances-next
```
