# 当前实现与资料来源

本文记录仓库当前代码行为和资料来源。当前资料维护见[后台工作流](EDITORIAL_WORKFLOW.md)，开发命令见[开发指南](DEVELOPMENT.md)。

明日方舟角色关系可视化网页。首页进入“干员”分区，以国家／阵营的粒子徽记和文字目录选择入口，再进入关系图。“联动”入口下再选择莱欧斯小队、Ave Mujica、S.E.E.S. 或彩虹小队。2026-09-20 接入已完成人工复核的重点 NPC：完整模式覆盖565位人物，收录4,266对确认相识、1,445对单向知晓，共5,711条关系；这不是全游戏人物全集。

从阵营进入时先显示该阵营的人物与内部关系；点击人物后显示其完整跨阵营关系，再点击另一个人物继续探索。全局搜索覆盖当前资料范围内的全部人物。关联超过36人时，默认显示分组总览；点击分组后单独浏览这一组，按可用画布大小分页，并保留主角。可通过本组名录搜索、定位或查阅证据，“全部分组”恢复之前的总览与视角。底部保留全部展开、收起，支持别名搜索、拖动、平移缩放及历史恢复。凯尔希在干员版有197位相关人物，完整模式有235位，均可访问；完整流程与验证见 [关系分组交互](RELATION_GROUPS.md)。

人物泡泡轻微漂浮，展开时从原分组位置散开，分页内错落聚拢。关系线默认按需显示：悬停或键盘聚焦人物时突出其关系；“显示选项”可打开全部连线、周围关系或暂停泡泡动态。详细行为与验证见 [泡泡动态与连线](GRAPH_MOTION.md)。

展示连线采用无箭头的实线曲线。相识或单向知晓的判定及明确方向只显示在两人关系详情里，详情同时提供关键原文和来源。分组只是显示层聚合，同阵营不创建关系，折叠不会改变原始人物或边。

## 运行

当前版本采用 Vue 3 + TypeScript + Vite、Django + DRF、PostgreSQL。游客浏览图谱、人物档案、关系原文和来源，进行六步连线，并可提交独立匿名反馈。页面提供 GitHub Issues 入口；旧登录/注册、收藏、评论、举报和账号投稿默认关闭，已有普通账号也不能绕过服务端开关。资料范围支持“干员版”（396人、3,703条关系）和“干员与 NPC”（增加169名 NPC）。

`/sources/` 独立显示“来源与版权”，从首页/阵营页页脚、移动导航、图谱指南或游戏页脚可进入。页面提供素材来源、MIT 全文、前端依赖与字体许可链接及私有权利反馈，不加载图谱/游戏实例，也不依赖公开 GitHub 仓库来显示必要说明。待核实的素材使用依据仍按实际状态标注。

推荐 Python 3.12、uv、Node 24、npm 和 PostgreSQL。依赖安装、迁移、启动和专用测试库步骤统一见 [开发指南](DEVELOPMENT.md)；前端使用随源码提交的 [固定版本素材](RESOURCE_PACK.md)。开发模式可使用 SQLite，生产和数据库并发验收使用 PostgreSQL。

正式资料以数据库中已审核发布的版本为准，日常修改经[后台修订、审核、预览和发布](EDITORIAL_WORKFLOW.md)。`data/source/` 仅用于首次初始化基线及单向归档，不能通过重新导入覆盖后台编辑。默认 `FORMAL_DATA_MANAGED=1`，只有 DEBUG 本地兼容测试可以显式关闭，生产拒绝关闭。

本地入口为 [首页](http://127.0.0.1:5173/)、[干员分区](http://127.0.0.1:5173/#factions)、[凯尔希关系图](http://127.0.0.1:5173/?faction=rhodes&person=char_003_kalts#graph) 和 [管理后台](http://127.0.0.1:5173/admin/)。前端开发代理连接 8000 端口，同源提供 API、后台与后台静态文件。[匿名反馈](FEEDBACK.md) 使用独立 CSRF 保护和私有处理队列；[后台修订](EDITORIAL_WORKFLOW.md) 提供关联资料编辑、审核、版本发布和回退。旧账号邮件流程仅留作显式开启社区后的兼容能力，不是首版访客反馈的前提。

当前资料契约见 [资料格式](DATA_SOURCE.md) 与 [发布流程](DATA_RELEASES.md)。匿名反馈无需访客邮箱或邮件服务。

已导入 NPC 的本地库可直接查看 [干员与 NPC 目录](http://127.0.0.1:5173/?scope=all#factions) 和 [博士关系图](http://127.0.0.1:5173/?scope=all&person=npc_b99957887950ebfd#graph)。复核合并规则、头像来源、重建命令及验证记录见 [NPC 接入说明](NPC_IMPORT.md)。

历史静态原型可用 `node scripts/serve.mjs` 查看，需要另备 `dist/` 输入。日常开发不依赖该目录；通用容器配置位于根目录 `compose.yaml`。

首页正式内容与后续分区待定。当前视觉与交互根据只读参考工程 `arknights-rebuild` 适配；具体源码机制、事实与适配判断见 [学习文档](SOURCE_LEARNING.md)，当前字体、颜色、布局与动效参数见 [设计记录](../DESIGN.md)。

## 人物连线

顶部 `GAME / 游戏` 进入 [人物连线](http://127.0.0.1:5173/game/)，源码位于 `frontend/src/game/`。普通模式的入门、标准、挑战分别补全一、二、三处空位，点击候选不提前判定关系；每空可主动使用一次排除提示。六步探索保留候选人物列表；输入挑战由系统给定起点、终点，玩家自行填写人物，支持真名、异格、常用绰号和模糊匹配。双人判断先判断是否直接认识，不认识时再从候选池选择能同时连接两人的中间人；每轮 10 题按 5∶5 打乱出题，间接题保证有解，候选混入干扰项。第一步点击即判定，所选答案用浅绿或柔和红色反馈；中间人仍在确认后判定。四种模式共用原左右立绘，分别保存进度，旧六步存档可恢复到探索模式。

每条已收录连线均可双向通行，探索与输入模式六步内连接两端即可通关。四模式默认仅干员，默认禁用博士、阿米娅、凯尔希；旧存档保留原范围。支持搜索增删禁用人物、选择范围与连线题难度，应用规则后按过滤图谱确保能出题；过度限制时保留原题。普通模式接受有效替代答案；输入匹配不提前泄露可走邻居。连线题答案可展开多条有效路线，逐段查看原文；双人判断有连线的答案也可查原文。

38 种异格可使用各自名称、头像、精一／精二和背景特写出场，本局形象随进度保存。异格复用本体关系和正式人物 ID，禁用覆盖所有形态，不能用换形态重复经过同一人。

支持撤回、下一人提示、沿途关系原文、最短路线结算和浏览器本地进度恢复。左侧立绘跟随当前人物，右侧固定终点；点击灰色背景可交换精一／精二，两个阶段都使用半身特写作为背景。NPC 使用单层剧情立绘。页面复用原站字体、黑白与青色配色、细线和直角控件。玩法、算法、验证与维护入口见 [游戏说明](GAME.md)；算法验证执行 `cd frontend && npm run test:game`。

## 数据与素材

干员基线数据来源为相邻 `ArknightsRelationshipPilot` 的最终五列结果、最终人物对映射及唯一当前有效判定。生成器将901条单向关系全部转为确定的 `from/to`，保留稳定键，别名和异格使用已有身份体系。人物阵营来自现有游戏角色表，龙门纳入炎，无国家字段时采用明确组织或小队。字段全缺失时先读取 [归属补充表](../scripts/faction-overrides.json)，仍无结果才归“未归属”。按用户确认，Sharp、Pith、Touch、Stormeye、郁金香、Misery 归入罗德岛，干员版罗德岛83人；干员基线没有未归属人物，目录不显示空入口。原始核查结果不被改写。

NPC 扩展来自 `ArknightsNpcCatalog` 的重点名单、审读贡献与39项已保存人工意见，派生文件位于 `data/npc/`。完整模式新增整合运动、卡兹戴尔、汐斯塔及有实际人物的未归属入口；NPC 的分组表示资料归类，可能包含历史归属。12组条件叙事关系单独保留，不并入实际叙事图。

以下命令仅用于独立上游资料重建和历史核验，不是日常正式资料发布入口：

```bash
node scripts/build-graph-data.mjs --source ../ArknightsRelationshipPilot --output dist/data
node scripts/validate-graph-data.mjs --data dist/data --source ../ArknightsRelationshipPilot
```

`dist/data/graph.json` 提供初始图结构，`evidence.json` 提供初始原文和来源。新站点从数据库读取正式资料；图结构由 `/api/graph/` 返回，打开关系时单独请求该关系的证据。重新导出 JSON 不会自动覆盖数据库；新上游批次先形成资料差异，经后台修订审核，再通过带版本发布更新。公开图谱返回 `dataRelease` 与 ETag，资料读取保持单次响应的版本一致性。

头像来自用户指定的 [ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)，固定提交 `57ef5385c1ab1315fe4f2094f399b5c803bd71fc`。396张默认头像全部匹配，原始PNG均为180×180，已核验来源Git blob、SHA256和PNG结构。美术权利归相应权利人；来源库的“学习交流”说明不等于公开再分发授权，详见 [来源与许可状态](../THIRD_PARTY.md)。

新增169张 NPC 头像取自资料目录已经标注的 PRTS 游戏立绘，裁切为256×256本地 WebP，共约2.17 MB。原图网址、来源页、裁切范围与原图／输出 SHA256 记录在 `assets/npc-manifest.json`；5张通用立绘在人物资料中明确标注，均可打开来源页。

游戏另有 922 张完整构图立绘和 714 张精一／精二半身特写，覆盖当前 565 位人物，历史输入保留在 `dist/illustrations/`，当前构建从固定版本素材包恢复。干员资源固定于 2026-09-11 的 `fexli/ArknightsResource` 与 `ArknightsGameResource` 版本，NPC 复用上述原图；来源、校验、范围与重建方法见 [游戏立绘说明](GAME.md#立绘来源与维护) 和 `assets/illustration-manifest.json`。此库包含当前人物的基础／精一、可用精二和 NPC 立绘，不是全皮肤库。

`assets/manifest.json` 记录原始素材来源，`assets/fetch-assets.mjs` 与 `asset-plan.json` 用于按固定版本重新获取。网页使用WebP缩小传输体积，派生素材清单位于 `dist/avatars/manifest.json`。转换脚本 `scripts/prepare-avatars.mjs` 接受原始PNG目录、输出目录和可用Sharp模块绝对路径，转换只影响图片编码。

粒子素材从固定资源包恢复，来源及校验值见[资源清单](../assets/resource-manifest.json)，历史原型输入曾位于 `dist/assets/emblems/`。按用户指定，“联动”及其小队目录统一使用彩虹小队的既有粒子效果，四支小队仍保留独立资料与关系图入口；该共用图案是导航表现，不表示四支小队共用官方徽记。字体来源及维护见[字体记录](ASSET_LICENSING.md)。粒子在离开分区或页面不可见时暂停，支持系统减弱动态和无 WebGL 时的 Canvas 备用绘制。2026-09-21 移除手动散开和暂停按钮及其状态；粒子从画布外沿图案结构飞入：三角边框与塔身分别沿斜边、纵轴汇入，角枝分流，翼形两侧掠入，放射形沿尖刺收束，圆环沿切线绕入，斜纹平行穿入，对称主体弯曲合拢，蛇杖交织，联动倒三角与数字分层组装。`emblem-motion.js` 按徽记及实际目标点位置预计算三次曲线路径，随机错开起点、出发时间与速度，约 1.6 秒汇成图案。首页进入干员页时按新画布尺寸立即重播，重复数据同步不会重播缓存徽记。短激光尾迹跟随飞行速度，落定后消失；桌面同时最多 96 根引线，窄屏、低高度横屏及 Canvas 备用最多 48 根。保留鼠标／触摸局部扰动。Canvas 仅绘图，由外层普通容器接收指针，使右键使用含刷新操作的浏览器页面菜单；右键不触发点击涟漪，粒子区触摸拖动不触发分区切换。阵营页的透明内容层允许指针穿透，目录和按钮单独接收事件。参照用户提供的稀疏点阵截图，桌面从 10,000 调整为 5,000 点，窄屏为 2,400 点，低高度横屏为 1,200 点，Canvas 备用最多 2,200 点。采样分别处理轮廓与内部填充，最多 38% 的粒子优先保留边界、文字和细线，其余粒子在内部均匀分布；每格选择真实前景像素，保留细小空洞与文字间隙。提高单点可见度，并略加强轮廓粒子的亮度，避免减量后图案发虚。切换箭头位于阵营名称下方的操作行。浏览器回归入口为 `FRONTEND_URL=http://127.0.0.1:5174 node scripts/verify-particles.mjs`，使用隔离模拟 API。

当前固定资源清单包含 2,426 项、172,413,803 字节，随源码保存于 `assets/local/atlas-assets-24d6e8427efd2e90f29f1b7e/`。新增 190 项异格素材，原素材只有立绘索引扩充，其他文件摘要不变。前端构建先校验完整清单，再生成 `frontend/public/`；不从 `dist/` 复制素材。素材校验与构建方法见[开发指南](DEVELOPMENT.md)。权利状态保留为 `unreviewed`，许可核对边界遵循项目维护约定。

## 实现取舍

原生 SVG 和粒子模块保留在 `frontend/src/atlas/`，Vue 管理范围选择、资料详情、游戏和访客反馈；旧账号组件由服务端能力开关控制。原图形模块暂保留 JavaScript，新业务代码使用 TypeScript。保留现有布局与指针交互；后续若实测更大规模图谱成为瓶颈，再评估专用图组件。后台采用 Django Admin，反馈处理与候选编辑按权限分开；正式资料修改经后台修订审核与预览，由发布服务事务应用；Git 保存代码、初始化资料与单向导出快照。

布局位置及展开状态在本次页面历史中恢复，不写入服务端。刷新保留URL中的人物和可用历史状态，跨设备手动布局同步不在本版范围。缩放和拖动是探索操作，距离不代表人物关系强弱。
