# 更新说明

`/updates/` 展示已经发布的剧情修订与功能更新，按首次发布时间倒序排列，每页 20 条。入口位于首页、关系图、游戏和喜好导航；手机从菜单进入。访客可筛选分类、读取较早记录，并通过现有反馈表单补充问题。

## 后台维护

后台「更新说明」中新增草稿，填写稳定标识、分类、标题、摘要和每行一项的更新内容。页面和后台不设置独立的「感谢反馈」区块，需要致谢时直接写进该条正文，不自动套用固定模板。使用可公开的描述，具名致谢前确认对方同意。系统不从私有反馈、联系方式或审核备注自动生成正文。

保存后点击「预览更新说明」使用正式页面查看草稿。预览需要后台查看权限，接口禁止缓存；未登录或无权限的访问无法读取草稿。普通页面只读取已发布条目。

检查内容后，在后台列表选择「发布所选更新说明」。发布需要单独的「可以发布或撤回更新说明」权限；仅有编辑权限不能发布。剧情修订须先完成正式资料发布并关联实际的资料版本；功能更新在应用功能上线后发布。关联版本是维护者核对修订生效的依据，不自动判断文案是否覆盖某个关系。

已发布说明只读。需要改字时先撤回，编辑、预览，再发布；首次发布时间保留。表单使用版本号拒绝过期保存，发布与撤回写入后台操作历史。稳定标识保留不变，公开正文只按纯文本显示。

## 每次更新的记录方式

对访客可见的剧情或功能变化，准备对应说明草稿：先说具体变化，再解释影响；剧情提供可定位的章节或档案出处，致谢按本条实际情况选填。尚未上线的内容保持草稿。应用部署、资料发布与说明发布是三个独立步骤，不以代码合并或草稿预览代表完成上线。

本次首批说明已准备剧情纠错与「新增更新说明」两条。上线操作资料保存在仓库外；迁移 `0013_site_updates` 只新增更新说明表和关联，不更改既有人物关系或发布初始内容。

## 实现与验证

`SiteUpdate` 是独立的公开说明模型，与正式剧情资料修订分离。`/api/updates/` 支持分类和分页；`/api/updates/<id>/preview/` 仅供有权限的后台用户预览。公开响应只包含展示字段，正文无需 HTML 或 Markdown 解释器。旧 `acknowledgements` 数据库列保留以兼容已有记录和应用回退，后台与公开响应均不再单独使用，无需数据库迁移。

`make check` 和 `make check-postgres` 覆盖草稿隔离、预览权限、发布及撤回、版本关联、过期表单和分页。启动前端后运行 `node scripts/verify-updates-ui.mjs`，用模拟接口检查桌面/手机、筛选与浏览历史、反馈入口、草稿状态以及加载失败后的重试。模拟接口不代表真实资料已发布。
