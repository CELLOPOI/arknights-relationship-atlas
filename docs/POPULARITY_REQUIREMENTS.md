# 「喜好」功能开发需求

Status: implemented (V2；真实运行效果待观察)
Date: 2026-09-23

V2 已扩展为全形态目录、半身灰阶卡面、逐剧情 NPC、双上限加权与综合榜、50 次休息和双向切页。现行参数及证据见[统计说明](PREFERENCES_STATISTICS.md)和[V2 验收](PREFERENCES_V2_ACCEPTANCE.md)。下列首版任务描述保留设计沿革；旧的小批数量不再限定当前范围。

本文是首版及 V2 实现的验收依据。实际行为、与初始设计的取舍和证据集中见[运行说明](PREFERENCES.md)。产品目的、统计理由与参数以[策划案](POPULARITY_PROPOSAL.md)为准；实施任务见[开发计划](POPULARITY_DEVELOPMENT_PLAN.md)。本文的 R 编号用于关联任务与验收；真实流量、防刷效果与容量不由合成验证代替。

本次交付包括站点名称与导航更新，以及统一「喜好」页面内的人物随机比较、厨力支持、本命标记、形态偏好、榜单与趋势，以及包含精一、精二和服饰的皮肤视图。当前系统继续使用 Vue 3 / TypeScript、Django / DRF、PostgreSQL 和固定素材清单。普通用户全程可以免登录；不依赖重新开放旧账号社区。

## 1. 页面与身份

### R-01 入口和导航

站点显示名称为「方舟关系与喜好」，默认浏览器标题为「方舟关系与喜好」。功能导航为「人物关系 / 游戏 / 喜好」，首页、站点说明与来源入口保留。名称更新覆盖首页标题、导航品牌、页面标题及现有分享元数据中的站点名称；不因此修改仓库名称、稳定业务 ID 或部署地址。命名依据见 [PRODUCT.md](../PRODUCT.md#brand-commitments)。

新增统一「喜好」分区。人物与皮肤使用一个页面外壳，左侧以「人物」「皮肤」按钮切换，默认进入人物；按钮要有清晰的当前项和键盘操作。人物视图的随机选择、厨力支持、榜单与趋势、我的记录放在主体区域内，皮肤职业筛选位于皮肤主体右侧，三者不能混成同一级导航。

| 路径 | 用途 |
| --- | --- |
| /preferences/ | 同页默认人物视图，首先显示随机选择 |
| /preferences/?tab=characters | 显式指定人物视图；可切换厨力支持、榜单与趋势、我的记录 |
| /preferences/?tab=skins | 同页皮肤视图，显示干员网格及职业、名称筛选 |
| /preferences/?tab=skins&form=具体形态ID | 同页打开该形态外观详情；无效或撤下 ID 显示明确状态 |

左侧切换更新地址的 tab 状态与浏览历史，保持同一页面外壳和匿名身份。首次直接访问未带 tab 的地址显示人物，未知 tab 安全回到人物；form 参数只在皮肤视图解析。公共地址不携带私人投票内容或身份凭证。此前两条 /popularity 页面路径尚未上线，采用本契约即可；后端拟议 API 前缀与页面导航名称分开。

人物与皮肤分别保留本次页面会话中的搜索条件、滚动位置和未提交草稿；待答正式题以服务器状态恢复。切换不提交草稿、不派发额外正式题，也不重置额度。请求进行中切换仍正确处理原操作的响应，但人物视图隐藏时不自动请求下一题；切回后按最新服务器状态决定是否继续。草稿恢复时检查个人版本和名录版本，冲突需重新核对。皮肤详情关闭后返回该视图的原列表位置，左右控制面板不叠开。

桌面左侧为纵向切换区；手机保留左侧紧凑按钮，每项至少 44 像素触控高度并有可读文字。皮肤视图的职业按钮在手机主体工具区靠右，避免额外占用整列宽度。刷新、分享直链和前进后退均恢复地址指定的视图；刷新不承诺恢复未提交草稿，服务器已登记选择必须恢复。

人物档案提供对应人物的形态入口及带 tab/form 参数的外观链接。本体、异格、职业形态不止一个时，使用明确名称让用户选择。公共榜与皮肤结果可直接查看，不强制先投票。

当前 [main.ts](../frontend/src/main.ts) 通过路径动态加载入口，尚未配置上述页面。同一路径下的查询参数变化也必须由喜好页面响应，不能只判断 pathname 变化。接入需同时处理桌面/移动导航、浏览历史、服务端静态回退及全局事件卸载；人物和皮肤可按需加载内容组件，但共用一个顶层入口。

前端实现前须阅读用户指定的本地 `arknights-rebuild` 参考工程，学习字体与间距层级、导航、立绘/画廊布局、转场及移动端处理，并结合本项目实际组件适配。[参考资料](SOURCE_LEARNING.md)列出可定位的源码入口。参考工程作为只读学习资料；本项目的已定页面结构、交互和数据契约优先，最终构建不依赖外部工程目录，新增素材仍经固定清单交付。

### R-02 匿名参与与个人状态

服务器维护匿名参与身份，第一方安全 Cookie 用于恢复。前端不得提交一个任意 visitor ID 就获得该身份的写入权限。写请求具备 CSRF 防护、用途验证与限速；首次参与失败应可重试。

个人当前状态由服务器返回，包括额度、待答题、厨力名单、形态与皮肤选择、版本号、下次可修改时间。切换页面和刷新可以恢复；仅本地缓存不构成正式计票依据。个人接口与公共缓存分离，响应不得被共享缓存串给其他访客。

清除浏览器身份后无法保证找回，页面在需要解释恢复范围时明确说明。正式额度、票权不因登录提高；未来账号同步另行实施身份合并，首版不引入登录奖励。

## 2. 人物投票

### R-03 正式随机比较

两个人物以同等视觉面积并排展示，参考现有游戏的双立绘构图。题目为「这两位人物，你更喜欢谁？」双方使用当前候选版本固定的代表图、姓名与必要身份提示。投票前不出现票数、排名、强度、稀有度。

立绘可以单独放大，每边有明确选择按钮；点击放大、滚动、滑动不提交投票。跳过保持可见，可直接跳过，也能选不熟悉或难分高下。全部跳过不记胜负。

复用 [CharacterIllustration.vue](../frontend/src/game/CharacterIllustration.vue) 时提取或增加纯展示模式，禁用其背景换精英阶段操作，不继承游戏的起点/终点、路径、难度与提示状态。个人皮肤卡面不影响正式人物比较图。两侧素材条件不对称时应简化装饰，不能给干员额外播放多套形象而让 NPC 只有一张。

正式任务派发与答题为两个操作。等待服务器确认后才进入下一题；加载中防止重复点击，失败留在原题。客户端没收到响应不等于服务器没入库，重试必须返回同一处理结果。

### R-04 额度、配对与恢复

全部数值从服务端配置与[策划案第 1、3 节](POPULARITY_PROPOSAL.md)读取，前端不得自行另设额度。首版包含周额度、连续 28 天总额、人物展示上限、无序对位去重、待答题期限四组联合约束。

以下是必须满足的不变量：

- 派发时原子预留额度与人物/对位次数；GET 查询不派发新题，不消耗额度。
- 同一参与标识最多一题待答，多标签页恢复相同人物与左右顺序。
- 自然过期不返还派发次数；服务器确认的候选失效或资源故障才按审计规则返还。
- 跳过计入派发次数；刷新、失败重试、凭证续签不重复扣额，也不免费换题。
- 答题接受时间由服务器决定；统计入窗按接受时间，额度按首次派发时间。
- 左右随机；补齐曝光策略留存策略版本，不能由前端提供指定人物作为正式题。
- 页面显示实际可用情况和恢复时间。因候选不足暂时无法出题，不伪装为额度耗尽。

个人练习与正式模式有显式区别。练习不进入公共结果，下周也不补计；个人记录展示实际接受过的对局，数据不足时不制造完整个人排名。

### R-05 厨力支持与本命

提供姓名、别名搜索和人物范围筛选，可找到精选 NPC。临时编辑与已保存名单分开显示，确认时原子替换整份名单。支持槽位、本命子集与统一冷却遵循策划参数；不能把多份支持叠给同一人物，也不能以异格占用第二份支持。

撤下某支持时一并移除其本命标记；空名单用于撤回全部支持，并在确认前解释。版本冲突返回最新状态，不能静默覆盖另一个标签页的修改。未提交草稿可在本页面保留，提示失败后不丢失搜索与选择。

### R-06 形态偏好

以人物为投票对象、以该人物的合格形态为候选，保留一个当前偏好或「没有明显偏好」。只有一个形态时不制造形态冠军。形态票与人物票、皮肤票独立。

新增形态后保留旧登记；当前名录统计需要明确确认新集合。职业补丁形态使用可追踪映射，不能依据中文同名或 filename 合并。身份不明确时暂不开放该项。

## 3. 皮肤视图与交互

### R-07 干员列表

页面直接展示按八职业大类组织的干员网格；每个具体可玩形态一张卡片，本体与异格独立展示官方名称、归入自己的职业。默认「全部」按先锋、近卫、重装、狙击、术师、医疗、辅助、特种分组；组内使用固定资料顺序，最后以形态 ID 消除并列不确定性。分组标题位于网格外，不为每张卡叠职业角标。

每张卡的可见内容只有立绘与名字。允许必要的悬停、焦点边框和加载占位，不叠星级、等级、阵营、职业、皮肤名、票数、排名或已投勾选。完整的选择状态在详情及辅助技术名称中表达。

列表按形态名称、人物名和别名搜索。搜索与职业筛选取交集；结果为空时提示当前条件并能一键清除职业限制。投票不改变排序；关闭详情恢复到原卡片与原滚动位置。未完备的形态可以保留在目录中供查看，详情说明缺口，不能用部分皮肤发起正式投票。页面工具区显示已开放的目录覆盖范围。

布局目标为桌面多列、手机两列；竖幅比例、间距和姓名字号以[策划案第 5 节](POPULARITY_PROPOSAL.md)的初稿为起点，用实图调整。长名字允许两行，姓名区统一高度，不靠悬停才读全名。卡面选择合适的人像裁切，不能把眼睛、头顶或主要辨识部位裁掉；宽构图可配置专门焦点。

### R-08 右侧职业控制

皮肤视图右侧始终有可触达的「职业」大按钮，显示当前职业或「全部」，点击展开「全部 + 八职业」面板；切换到人物时隐藏该按钮与职业面板。左侧「人物 / 皮肤」按钮控制视图，右侧职业按钮只过滤干员。采用可核查来源的实际职业图标，同时显示文字；不使用分支职业、阵营徽记或猜画的图案代替。

桌面在右边保留按钮所需空间，展开面板可覆盖局部画布但不能截掉关闭入口。手机按钮放在主体工具区右侧，避开系统安全区，不额外挤压网格宽度；面板高度受可见视口限制，九个选项都可滚动到达。选择后收起，点击遮罩或按 Esc 可关闭；关闭后焦点回到触发按钮。当前职业用选中语义与文字共同表达。

按钮建议最小 56 × 56 CSS 像素，选项交互高度至少 44 像素。卡片和职业栏分属不同操作，不让点职业误触后方卡片。打开详情时收起职业面板，避免叠两层对话框。

### R-09 默认与投票后的卡面

默认卡面取当前形态的精一对应基础立绘。没有独立精一阶段则采用真实初始外观；职业补丁只有精二资源时，使用该形态真实可用的基础画面并在详情按实际阶段标注，不能借其他形态的精一图充数。默认展示永远不建立投票记录。

| 个人状态或操作 | 干员卡面 | 当前公共贡献 |
| --- | --- | --- |
| 从未选择 | 默认基础立绘 | 无 |
| 在详情预览或暂存比较，未确认 | 原已登记画面或默认 | 不变 |
| 服务器成功接受明确最爱 | 该选项对应画面 | 按当前名录与风控状态处理 |
| 保存「没有明显偏好」 | 默认基础立绘 | 只进入无明显偏好数 |
| 提交失败或状态不明 | 先保留已确认画面，查询受理结果 | 不用前端猜测 |
| 新名录出现，旧选择仍合法 | 保持旧选择画面，详情提示确认 | 未确认前不进入当前名录明确选择数 |
| 所选图片暂时加载失败 | 保留选择，显示占位并可重试 | 不自动撤票 |
| 所选项正式撤下 | 回退默认画面，详情解释 | 退出当前合格结果，保留历史 |
| 主动撤回 | 默认基础立绘 | 无；撤回事件保留审计 |

同一浏览器刷新、切换职业或返回列表后恢复服务器个人状态。只替换这位干员的画面，不将所选皮肤扩散到其异格或公共人物题目。公共榜变化不会改变个人卡面。

### R-10 外观详情与完整候选

桌面使用宽详情面板，手机使用整屏详情层。提供明确返回、干员名称、全部外观目录、完整立绘预览、最多三个临时比较位和确认按钮；结果为独立视图，可随时查看。关闭未提交草稿不改票，返回保留列表状态。直接链接进入详情时返回目录。

精一、精二、每套合格命名服饰均可作为正式最爱，权重相同。默认进入详情无新预选；已有记录则指出「当前选择」，临时候选与已保存项区分。最终提交只确定一个最爱，或主动选择「没有明显偏好」。图片上的放大与比较动作不等于确认投票。

阶段缺失、完全相同画面、同一套服饰的静态/动态/头像变体必须去重。没有命名服饰、但有不同精一与精二时可以投；完整目录只有一张不同外观时可以看，不开放比较票。NPC 不进入此入口。

外观候选按参与标识和名录版本稳定随机排序，包括基础阶段；同次查看中不跳位。完整图库使用相同背景和可比较尺寸，保留完整构图，可放大；平铺入口的人像裁切不用于判定全幅好坏。临时只看服饰的筛选不改变当前正式候选集。

图库必须提供所有合格选项，不能只出现已售卖、已拥有、当前高票或成功加载的选项。每项提供可辨认的已加载预览，全幅大图按需加载，不要求逐张打开原尺寸图片。客户端预览失败允许重试且不隐藏选项；任一正式候选预览尚不可用时，暂停确认。服务器确认资源故障时暂停该形态新正式写入，修复后恢复；保留已有登记与最后成功结果。

### R-11 保存、冷却与名录变更

一个匿名参与标识对一个形态最多一份当前记录，可覆盖任意多个干员，不共享随机题额或厨力名额。服务器返回选择、当前名录版本、个人状态版本、确认状态及下次可修改时间。保存成功后更新卡面及详情；公共统计异步更新并标注时间。

改选原子替换旧选择。冷却按形态计算；撤回可立即停止贡献，但再次登记不得绕过剩余冷却，撤回也更新防刷修改时间。保存「没有明显偏好」同样属于修改；重复提交相同选择与同一版本不新开冷却、不增加贡献。因候选正式撤下需要纠正选择时，由服务器提供有审计的纠正通道，不让前端自行跳过冷却。

新候选集公布后提供「保持原选择」「重新选择」。冷却期间可以确认仍然合法的旧选择，只更新名录确认版本；改选仍受冷却。确认旧名录、未知皮肤 ID 或不属于此形态的选项必须被拒绝。更新提示与姓名勘误区分，普通文字/压缩修复不要求重新确认。

## 4. 榜单与统计

### R-12 分开的结果口径

提供随机喜好、厨力支持、本命、近期支持变化、形态偏好和皮肤偏好；V2 另提供明示为“近期随机好感 + 当前支持”的70/30并列百分位综合指数，不能混入其他票池或称统一84天民意。随机榜展示 84 天与 28 天窗口；支持变化使用 7/28 天当前状态差值；形态与皮肤显示当前名录下已确认的最新登记。具体门槛、模型与频率集中维护在[策划案第 6 节](POPULARITY_PROPOSAL.md)。

每份结果都返回采样起止时间、生成时间、名录版本、算法版本、实际数量及样本状态。开站不足窗口长度时显示实际积累天数；汇总失败继续显示最近成功结果及延迟状态；没有历史时显示空状态，不绘制假曲线。

随机榜使用带正则化的 Bradley–Terry 模型，并处理不连通、全胜全败、少量对手、循环偏好与参与者贡献不均。不确定性按参与标识成组计算；区间不能称为全体玩家民意误差。直接对位页使用实际正式对局，模型概率另行标注。

厨力占比采用有至少一位有效支持的参与标识作分母，可以合计超过 100%。本命数量单列。形态/皮肤占比的分母是该对象、该版本下有明确选择的标识；没有明显偏好和撤回分别处理。仅过滤服饰列表时不偷偷改变分母。

### R-13 时间变化与纠错

每日固定时点保存快照，并保存窗口、候选、算法与素材展示版本。直接名次箭头仅比较相同统计口径，遇到候选或算法变更、身份合并、显著展示图变化时保留节点和说明。新入选人物不显示从零名冲到某名。

采用滚动窗口，旧票退窗可能改变结果；厨力净增使用两个快照相减。反复移出又加回的按钮次数不能变成热度。异常排除产生修订版本和原因类别，不静默改历史数字。原始明细保留期之外的快照不得声称可以完整重算。

## 5. 资料、素材与服务契约

### R-14 名录与素材

三层稳定关系为人物 → 可玩形态 → 外观。名录至少记录形态所属人物、职业、公开名称、基础展示外观、完整候选、各项资格状态、生效时间和版本。素材记录原始来源、固定提交/文件校验、全幅图与卡面缩略图、尺寸、裁切焦点、素材修订号。

身份与职业来源须覆盖普通干员表及职业补丁表；精英阶段来源须覆盖常规和补丁的基础映射。禁止把 `skin_table.json` 所有记录直接开放投票，也不把有名称的记录数当作已上线完整皮肤数。

名录流程为生成候选、人工核对、差异预览、发布版本。引用正式已发布人物 ID；需要修正人物归属时，经既有资料审核发布。皮肤目录是新增资料类型，应在开发中明确其审核与原子发布服务，不能以复制 JSON 到前端来覆盖线上有效目录。素材先部署、核验，再发布引用它的名录；失败不能发布半套目录。

资源通过固定清单交付，运行时不热链上游浮动分支。网页按视口加载卡面缩略图，打开详情才加载该形态大图；不在首屏请求全部干员的所有皮肤。记录源码及第三方来源，遵循项目现有素材边界与许可状态。

### R-15 数据实体和事务边界

拟议实体以下列职责划分，具体模型名可调整，不强制新服务或新数据库：

| 实体 | 必须约束的内容 |
| --- | --- |
| 匿名参与身份 | 安全凭证、状态、创建时间；私有信息不出公共接口 |
| 候选名录版本与条目 | 人物/形态/外观关联、资格、资料及素材版本、有效期 |
| 派发任务和展示记录 | 同标识单一待答、不可变双方与左右、题目期限、额度归属 |
| 正式比较结果 | 一题一最终结果；选择或跳过；受理时间；风险状态 |
| 厨力名单及版本 | 一份当前名单、本命子集、原子替换、冷却 |
| 形态/外观当前选择 | 对象与身份唯一、可空的明确偏好、无明显偏好状态、确认版本、冷却 |
| 变更事件和风险审计 | 保留旧新状态、幂等操作键、排除原因与纠正范围 |
| 统计运行及快照 | 输入截止点、参数/算法版本、数量、收敛状态、修订关联 |

派发与额度预留在一个事务内；任务消费与正式结果入库在另一个事务内原子完成。唯一约束与 PostgreSQL 行锁共同保证并发，不能只靠应用进程内锁。厨力、形态和皮肤写入执行版本检查；同操作键重放返回原结果，不同内容复用旧键返回冲突。

删除明细不能删除仍然有效的当前支持、皮肤选择、名录确认或必要身份关联。缓存清空后能够从持久记录重建当前结果；清理与备份恢复需测试。保留周期和匿名防刷能力边界以策划案为准。

### R-16 已实现 API

已落地接口前缀为 `/api/preferences/`；完整字段与错误码见[接口契约](PREFERENCES_API.md)。GET 只查询，派发、提交与改选均为写操作。公共读与私有读明确分开。

| 接口用途 | 方法与路径 | 关键返回或约束 |
| --- | --- | --- |
| 初始化匿名参与 | POST /api/preferences/identity/ | 同浏览器身份恢复；CSRF 与风险策略 |
| 读取个人状态与额度 | GET /api/preferences/state/ | 服务器时间、实际额度、待答题、个人版本；禁止共享缓存 |
| 派发或恢复正式题 | POST /api/preferences/tasks/ | 幂等、任务 ID、双方、过期时间、额度；不能指定对手 |
| 提交题目 | POST /api/preferences/tasks/:id/answer/ | 选择或跳过、操作键；成功、待确认或已处理结果 |
| 读取/替换厨力 | GET / PUT /api/preferences/supports/ | 整份名单、版本、本命子集、冷却 |
| 读取/替换形态偏好 | GET / PUT /api/preferences/choices/form/:personId/ | 归属检查、名录版本、个人版本 |
| 读取公开外观目录 | GET /api/preferences/catalog/ | 职业、形态、覆盖状态、固定素材引用；不含私人选择 |
| 读取个人皮肤状态 | GET /api/preferences/state/ | 用于恢复列表卡面；无操作令牌进入公共缓存 |
| 保存外观偏好 | PUT /api/preferences/choices/skin/:formId/ | 明确选项、无明显偏好或撤回；版本与冷却 |
| 确认新名录 | POST /api/preferences/choices/skin/:formId/confirm/ | 只能确认当前仍合法的旧选择；同版本重复不加票 |
| 查询结果与历史 | GET /api/preferences/rankings/、trends/、pairs/ | 榜种、对象、窗口、版本和样本状态，不返回参与者明细 |

写入统一处理：参数非法、归属不符、旧名录、个人版本冲突、冷却、风险验证、限速、功能暂停、资源不完整和服务异常。机器错误码保持稳定，前端转为直接的中文操作提示；返回可恢复时间或最新版本，不能全部显示「投票失败」。风险暂缓的记录可显示个人已登记，但公共贡献明确为待确认，不能混同已入榜。

### R-17 后台与运行

投票业务独立开关控制读取、写入与各入口；关闭投票不必关闭图谱或游戏，也不重开旧社区写接口。提供候选审核、暂停写入、可疑记录复核、重算和任务运行状态。管理动作授权、CSRF 与审计沿用项目边界，不提供直接编辑某人物总票数的常规操作。

定时聚合按同一输入截止点计算，幂等运行、避免并行互相覆盖，失败保留前次快照。首版可采用管理命令加调度契约；未证明需要前不引入独立队列系统。访问风险信号有清理周期，IP 不等同独立人物；验证供应商需实施时在目标访问环境确认。

## 6. 验收清单

所有场景使用合成数据或可丢弃的隔离数据库，不能对业务数据库刷测试票。构建检查、浏览器模拟和 PostgreSQL 并发验证分别记录范围。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A-01 | 新游客打开皮肤页 | 看到按职业组织的列表，默认基础图；没有自动产生任何票 |
| A-02 | 选择精二或命名服饰 | 成功后仅对应卡面替换；切职业、返回、刷新后保留 |
| A-03 | 预览、取消、超时、重复提交 | 预览不改票；未知结果可查询；重试只计一次 |
| A-04 | 八职业、长名、异格、阿米娅补丁 | 职业与形态映射正确，长名可读；没有借图或伪造精一/精二 |
| A-05 | 没有服饰但有精一精二；只有一种外观 | 前者可以投，后者只能看，不产生 100% 冠军 |
| A-06 | 新皮肤发布、旧项撤下、图片失败 | 保留旧个人登记；重确认规则正确；故障不自动改票或缩小名录 |
| A-07 | 冷却、撤回、无明显偏好、其他干员首次投 | 对象冷却准确，撤回不绕过限制；不同干员互不占额 |
| A-08 | 双标签出题、跳过、跨周与 28 天边界 | 单一待答题、联合额度一致，跳过无胜负；过期/作废区别正确 |
| A-09 | 厨力名单、别名重复、本命、并发改选 | 槽位和子集满足规则；旧版写入冲突；聚合正确撤回旧项 |
| A-10 | 循环偏好、全胜全败、断开的比较网络 | 不制造精确名次；模型与聚类不确定性可复验 |
| A-11 | 统计版本变化、少样本、无历史、修订 | 口径、样本和时间可辨认；没有假趋势与跨版本箭头 |
| A-12 | 共享 IP 与异常自动化两类模拟 | 不按共同偏好直接删票；隔离、复核、恢复可以追踪和重算 |
| A-13 | 手机、键盘、辅助技术、减少动态 | 职业栏和详情可开关、焦点正确、主要动作可达，无横向溢出 |
| A-14 | 图片延迟、身份查询延迟、缓存清空、备份恢复 | 不闪成别人的卡面，不丢当前票；恢复后版本、额度和记录一致 |
| A-15 | 从干净构建打开图谱、游戏、来源及新增直链 | 固定素材齐全，旧功能与导航正常；不依赖相邻资料工程 |
| A-16 | 站点名、浏览器标题、功能导航与分享元数据 | 使用已定名称，顶层只有一个「喜好」入口承接人物与皮肤 |
| A-17 | 左侧切换、带参数直链、刷新及前进后退 | 同页正确切换和恢复；不重复派发、扣额或提交草稿；职业按钮仅皮肤可见 |
| A-18 | 手机左右控制、提交中切换与旧草稿恢复 | 左侧切换可达，右侧职业不挤压两列卡片；异步结果不串视图，版本冲突不覆盖新状态 |

浏览器至少覆盖 1440 × 900 桌面、390 × 844 手机、320 像素窄屏和低高度横屏。网络检查应确认首屏只请求必要卡面、不会预载全站大图；先记录资源量与交互基线，再据实设定优化预算，不能用未测数字宣称性能合格。

首批测试资料需覆盖八职业、本体与异格、无精二干员、仅精一/精二、单一外观、多套皮肤、只有精二的职业补丁、长名字、极宽构图及缺图。首批外观数量不代替这些类别覆盖；未完成素材的形态在开放范围中如实排除。
