# 后台资料维护验收

本验收覆盖[后台工作流](EDITORIAL_WORKFLOW.md)：关联资料草稿、审核、带版本预览、事务发布、反馈结案、快照导出和历史版本回退。旧候选可纳入修订，正式资料表保持只读，首次后台发布后拒绝 Git 包覆盖。

## 自动检查

在项目根目录执行 `make check`；发布锁、并发竞争和约束须使用专用 PostgreSQL 测试库执行 `make check-postgres`，环境要求见[开发指南](DEVELOPMENT.md)。SQLite 跳过的锁测试不能视为通过。

回归须覆盖关联人物、阵营、身份、关系和证据，草稿隔离、证据完整性、审核冻结、权限、CSRF、过期页面、退回后旧预览拒绝、反馈版本变化、反馈结案失败整批回滚、数据库漂移、头像校验、只更新素材版本、旧候选接入、基线冲突恢复、快照隐私隔离、回退及差异分页。

## 浏览器检查

`scripts/verify-editorial-ui.mjs` 仅对回环地址的可丢弃 PostgreSQL 测试站写入。准备 `atlas.test_releasing` 的 `test-1` 基线、配套资源清单及维护者测试账号，凭据 JSON 包含 `username`、`password` 和测试反馈 `feedback` ID，保存在 Git 之外。

```bash
ATLAS_EDITORIAL_TEST_WRITES=1 BASE_URL=http://127.0.0.1:5173 EDITORIAL_TEST_AUTH=/path/to/private/editorial-test-auth.json node scripts/verify-editorial-ui.mjs
```

脚本从测试反馈创建修订，新增人物、单向关系及带行号和版本的独立证据，完成审核、预览和发布，确认公开 API 更新、反馈结案与 ZIP 下载，再从历史版本创建回退并发布。检查桌面和手机的人物表单、证据表单、修订差异、发布预览及回退预览，页面不得出现脚本错误或横向溢出。报告和截图写入 `.runtime/verification/editorial/`，测试账号与反馈不得写入业务资料。

## 全量资料往返

涉及资料编译、发布或回退结构的变更，在另一个隔离数据库中从 `data/source/` 初始化。记录基线，完成一条虚构修订的审核、发布和关联反馈结案；导出 ZIP 后重新编译，确认资料摘要与已发布版本一致。回退到初始化版本后，正式资料逐字段一致，测试账号和私有反馈仍保留。条件叙事和来源贡献不得在往返中丢失。

这套检查验证应用功能与资料往返，不包含公网环境、容量或真实设备验收。升级已有数据库须执行增量迁移并保留已维护资料，不能重复应用初始包。每次检查记录所用提交、数据库类型和实际结果，不沿用旧版本的测试数量或通过结论。
