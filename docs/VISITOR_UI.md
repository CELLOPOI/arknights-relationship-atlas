# 访客界面与反馈

WEB-01 在现有 Vue 页面上增加 GitHub Issues 和匿名反馈入口，沿用黑白层次、青色操作与原生 dialog。图谱和 `/game/` 顶栏均可打开反馈；人物档案、关系档案及游戏关系依据可带上当前资料对象，表单中显示对象名称并允许移除。

`/api/session/` 明确返回 `communityEnabled: true` 时才显示旧账号社区功能。默认值、缺失字段和会话读取失败均关闭社区入口；此时不请求评论或收藏，人物详情、关系方向、原文和来源仍可独立读取。旧社区代码保留，权限最终由后端控制。

匿名表单向 `/api/feedback/` 提交类型、说明及可选目标、来源链接、联系方式。提交前刷新 CSRF cookie，提交中禁用表单以避免重复；成功显示收件确认，失败保留输入，限流显示服务端 Retry-After 秒数。表单说明私有处理及联系方式用途，不自动向 GitHub 提交。关闭弹层不会清空未成功提交的正文，同一页面再次打开可继续填写；刷新或离开页面不会保存草稿。

反馈与详情采用原生 dialog，支持键盘焦点约束、Escape 关闭和关闭后返回触发按钮。图谱的 Escape 与搜索快捷键会避开反馈弹层。移动端表单内部滚动，标题及关闭按钮保持可达。

本地验证使用 `npm --prefix frontend run typecheck`、`npm --prefix frontend run test:game`、`npm --prefix frontend run build`。启动前端开发服务后，从根目录运行 `FRONTEND_URL=http://127.0.0.1:5174 node scripts/verify-feedback-ui.mjs`。脚本使用项目 Playwright，并拦截所有 `/api/**` 请求；不会把反馈写入业务数据库。覆盖桌面 1440×900、手机 390×844，旧账号在社区关闭时不可见、人物与原文读取、对象带入和移除、提交中禁用、429 保留输入及重试、成功确认、Escape 焦点恢复和游戏入口。

验收截图输出到 `.runtime/verification/feedback/`。浏览器验收验证了前端行为与约定接口，未替代真实后端 CSRF、限流、数据库隔离或公开部署验收；后端这些边界由其独立测试覆盖。未测试真实手机软键盘及全部浏览器引擎。
